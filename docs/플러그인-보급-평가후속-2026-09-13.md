# 플러그인 보급 평가 후속 — 2026. 9. 13.

수정과 현재 PC의 후속 시험을 수행했다. **배포 판단은 보류**다. 확인된 두 결함과 실앱 시험에서 추가 발견한 Windows 훅 결함을 수정했다. 배포 허가·개인정보 검토와 일부 인수 조건은 남아 있다.

이 문서는 구현자가 수행한 후속 검증이다. 최초 독립 평가 176행을 새로 독립 평가한 보고서는 아니다. 최초 점수 **pass 56 / fail 3 / pending 2 / blocked 115**와 평가 기준을 보존했다. 새 결과로 최초 점수를 덮어쓰거나 부분 관측을 정식 pass로 승격하지 않았다.

## 현재 PC에서 수행한 시험

1. **회귀시험 75개 통과**: 배포 런타임 36, 훅 어댑터 25, 훅 수명주기 3, 배포 자산 4, 프로파일 주석 2, 런타임 신선도 5. 개발 회귀시험 수이며 앱 인수 점수가 아니다.
2. **기존 5종의 등록 승인 반영 확인**: 실제 사용자 원문 `기존양식 5종 승인`과 등록 파일/검토 해시를 대조했다. 목록 및 등록 버전 `prepare`가 작동한다. 양식 원본과 승인 등록 파일은 이번 시험 전후 동일하다. 이 승인은 새로운 공문 문안 승인이나 W1/W2 검토 평점으로 전용하지 않았다.
3. **5종 전체 CLI 흐름**: 평가용 가상 입력으로 build → validate → status → deliver, 총 20명령 성공. 실제 한글 COM을 직렬 실행했다. 운영 원본·실제 학교 공문·OneDrive를 시험 대상으로 쓰지 않았다. 사람의 새 문안 승인과 동료 교사 최초 사용을 통과한 실적은 아니다.
4. **설치 경로 변경**: 시험 설치 A를 다른 이름으로 보존하고 설치 B로 재연결했다. 등록 파일 해시와 양식 선택을 유지했다. 소유한 훅만 업데이트/제거하는 시험도 통과했다. 구·신 정식 배포 패키지를 앱에서 설치/제거한 시험과는 구분한다.
5. **실제 Codex 앱 번들 CLI 0.153.4 / gpt-6-astra**: 정상 `/hooks` 검토·신뢰 후 apply_patch 수정·삭제·이동·혼합 패치, PowerShell 쓰기, junction, 한글 경로 변경을 사전 차단했다. 새 출력과 정상 복사는 성공했고 보호 원본 해시는 유지됐다. 시스템 PATH의 이전 Codex CLI로 대체하지 않았다.
6. **실제 Claude Code CLI / claude-sonnet-5**: Write·Edit·Bash 쓰기, 삭제·이동·junction·복합 쓰기를 차단했다. 원본→새 출력 복사 및 별도 무표시 형제 폴더의 docs 수정은 성공했다. 이전 VS Code 평가와 같은 호스트라고 간주하지 않았다.
7. **실행 불가 진단**: 두 앱에 프로세스별로 존재하지 않는 Python 경로와 잘못된 runtime.json을 제공했다. 실제 쓰기 호출이 차단되고 보호 미검증으로 안내됐다. 운영 Python·한글·보안모듈은 제거하지 않았다.
8. **Stop와 W2**: 두 앱에서 고의로 깨진 HWPX가 실제 종료 검사에 실패했다. 이후 미변경 파일은 재검사를 생략하되 저장 상태 `ok=false`를 유지했다. 제출 방법 없는 가상 수신 공문에 대해서는 방법을 질문하고 회신 시행문/내부결재·승인·발송을 임의 확정하지 않았다.
9. **현재 Codex Desktop MCP**: 실제 kordoc 읽기와 학교 업무지침 조회가 작동했다. 실제 `patch_document`/`fill_form`의 보호 원본 덮어쓰기는 PreToolUse에서 차단됐고 해시가 유지됐다. 이 구현 세션의 결과를 독립 설치 또는 Claude MCP 인수로 전용하지 않는다.

## 관측 한계와 보존한 실패

- 최초 Claude 훅은 경로 오류로 실패했고, 두 번째 후보에서는 제한시간 취소로 가짜 원본이 변경됐다. Codex의 exit 전달 수정 전 후보도 보호 쓰기를 허용했다. 이 실패 기록과 수정 전후 사본을 삭제하지 않았다. 최종 보호 근거는 수정 후 실제 호출과 원본 해시다.
- Codex 진단 중 잘못 인용한 임시 명령은 시험 준비 오류로 보존했다. 이를 앱에 pre 이벤트가 없다는 증거로 사용하지 않았다.
- 처음 만든 내부 `plain-project`는 부모 `.hwpdoc` 표시를 상속하므로 무표시 조건이 아니었다. 별도 형제 fixture로 보완했다. Claude는 성공했으나 Codex는 앱 자체 workspace-write 경계에서 거절됐다. Codex의 이 행은 부분 확인이며 hwpdoc 오차단이라고 판단하지 않는다.
- 미신뢰 상태에서의 실제 쓰기, cwd 자체가 무표시인 별도 앱 세션, 동일 단계 2회 실패 후 한도 종료의 완전한 실앱 변형은 미완료다. 한도 단위시험을 실앱 결과로 승격하지 않았다. 실제 로그에서 관측한 한 번의 실패 후 미변경 검사 생략을 2회 한도 통과라고 부르지 않는다.
- Claude는 정상 복사를 보호 공백으로 잘못 설명했고 가상 원문에 이미 있는 값도 재확인했다. 복사 동작 자체는 명세에 맞고, 설명의 과잉 해석은 별도 사용성 관측이다. UTF-8 최종 집중 시험에서는 한 번 호출 지시와 달리 추가 도구 탐색이 있었으므로 해당 transcript를 독립 절차 준수 pass로 사용하지 않는다.
- 앱 통합 시험은 `code-v4` 스냅샷으로 수행했다. 이후 실행 코드 차이는 `hook.ps1`의 UTF-8 출력 설정이며, 두 셸 회귀와 실제 Claude 오류 호출로 집중 확인했다. 이후 Codex 전체 통합 시험을 다시 수행했다고 주장하지 않는다. 최종 소스와 차이 해시는 별도 기록했다.
- 시험 TUI에서 필요한 합성 프로젝트 훅만 일반 절차로 신뢰했다. 우회 플래그나 시스템 실행 정책 변경은 없었다. 시험 중 의도치 않게 숨겨진 Windows 쓰기 가능 경고는 다시 표시하도록 복구했고 다른 설정은 유지했다. 사용자 운영 훅을 일괄 재설치하거나 앱을 업데이트하지 않았다.

## 배포 판단과 남은 순서

현재 파일 해시로 `build_distribution.py --rights distribution/rights.pending.json`을 다시 실행한 결과 **exit 2, status=blocked, release_ready=false**다. 권리 미확인 70건, 개인정보 검토 미확인 70건, 의존성 라이선스 조건 8건이다. 배포 패키지를 생성하거나 외부에 게시하지 않았다.

1. 권리·자산 검토를 마친다. Canine89/hwpxskill의 사용·재배포 허가와 PyMuPDF의 AGPL/상용 사용 조건 등 미확인을 해결해야 한다. 기존 5종 등록 승인은 배포 권리 승인과 다르다. [기존 라이선스 원문 확인 보고서](배포-라이선스-원문확인-2026-09-13.md)의 미해결 사항을 유지한다.
2. 원본·사람 판독/문안 승인·교사 사용이 필요한 시험 자료를 확보한다. 자동 생성한 승인·판독 기록으로 대체하지 않는다.
3. 허가된 패키지가 준비되면 현재 PC의 격리 설치에서 남은 앱 인수 항목과 업데이트/제거를 수행하고, 새 소스 해시로 독립 평가를 남긴다. 외부 PC 시험은 이 작업 범위에서 계속 제외한다.

이번 결과는 개발 사본의 수정과 현재 PC에서 관측한 동작에 대한 근거다. 정식 배포 승인이나 모든 앱/셸의 완전한 보호를 보증하지 않는다. 운영 원본·기존 승인 등록·최초 평가 matrix·평가 기준의 해시 불변을 확인했다.
