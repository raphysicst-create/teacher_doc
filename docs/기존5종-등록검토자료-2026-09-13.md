# 기존 슬롯 양식 5종의 등록 검토 자료

2026. 9. 13. · Hwp_doc

## 실제 검증 결과

5종 모두 다음 8단계를 통과했다: 구조 검사, 네임스페이스, finalize, layout, 새 프로파일 생성, 한글 열기, PDF 대조, 전체 페이지 PNG 생성. 모두 기준/사본 1쪽이다. PDF 앵커 발견율은 모두 1.0이며 순서 비율은 일반 가통/예산/회의록 1.0, 회신형 0.974, 고사안내 0.917로 기존 검사 기준을 통과했다. 실패 기준을 바꾸지 않았다.

원본 사본을 별도 PDF로 내보내 같은 120dpi PNG로 렌더한 결과, **5종 모두 원본과 등록 사본의 페이지 PNG SHA256이 동일**했다. 페이지 수만 같다는 뜻이 아니라 이 PC의 같은 렌더 조건에서 픽셀이 동일했다는 증거다. 다른 PC·다른 한글 버전의 배치를 보증하지는 않는다.

에이전트가 실제로 5개 PNG를 읽었다. 일반 가통은 제목/안내 상자/하단 날짜·명의, 회신형은 일정 5행/절취선/서명란/회신표 아래 날짜·명의, 고사안내는 고사표와 출제표, 예산은 제목·관련·본문·붙임, 회의록은 협의 표와 중첩 출제표를 확인했다. 회의록의 일부 비율 문구 줄바꿈과 참가자·비고 공란은 원본과 동일한 상태다. 실제 사용자 확인으로 기록하지 않았다.

운영 원본과 등록용 original.hwpx 5종의 해시는 가져오기 당시와 동일하다. 성립전예산요구의 template.hwpx는 원본과 파일 전체가 동일하다. 나머지 4종은 Contents/section0.xml의 줄 배치 캐시만 제거됐고, 그것을 제외한 XML 정규화 결과와 다른 ZIP 엔트리는 동일하다. 제거한 linesegarray는 일반 43개, 고사안내 115개, 회신형 58개, 회의록 83개다. 표 구조·header·미리보기·메타데이터·이미지를 바꾸지 않았다.

성립전예산요구 layout의 body_paragraph_without_visible_indent 경고 1건은 원본 승계 상태로 기록했다. 단계별 원문 출력은 각 registration.json에 있다. COM 작업을 직렬 실행했고 종료 후 잔존 Hwp 프로세스는 없었다.

## 기록 위치와 다음 처리

각 등록 폴더 `.hwpdoc/templates/<양식>/legacy-1/`에 다음을 남겼다.

- original.hwpx, template.hwpx, mapping.json, slots.json, budget.json, structure.json: 현재 검토 대상과 해시.
- mapping.review-proposal.json 및 mapping.review-notes.md: README/실제 슬롯 대조 제안.
- review.pdf, preview/page-001.png: 검토할 현재 사본.
- original-review.pdf, original-preview/page-001.png, original-render-comparison.json: 원본 렌더와 동일 픽셀 비교 증거.
- registration.json: 상태 `awaiting_review`, 기계 검증 8단계 pass.
- review.draft.json: `confirmed=false`; 확인자·확인시각·확인내용은 비어 있음. review.json은 생성하지 않음.

출처 종류는 기존 이관 초안의 unconfirmed를 보존하고, 네이티브라고 추정해 렌더를 생략하지 않았다. 문서에 남아 있는 옛 날짜/사업명/학교 표시는 운영 양식의 기존 문안이며 새 업무 값으로 승인하는 대상이 아니다. 업무 생성 시 기존 문안 확인·관련번호 근거·복사 잔재 검사·전체 검증을 계속 적용한다.

[개선계획 3단계](C:/Users/22/Desktop/maintain/Hwp_doc/docs/플러그인-보급-개선계획.md)의 “사람이 등록 정보를 확인한 뒤 전환한다”에 따라, 위 자료에 대한 실제 확인을 받은 뒤 해당 현재 해시의 등록 확인 기록을 수리한다. 이번 기계 준비 결과로 자동 등록하지 않는다.

기존 구현 최종대조 보고서의 “등록 초안” 상태를 이 자료의 “기계 검증과 시각 비교를 마친 검토 대기”로 보완한다. 외부 컴퓨터 시험, 두 앱 실제 인수, 배포 권리 확인은 이번 기록으로 완료 처리하지 않는다. 이번 작업은 양식 이관 준비이며 별도 평가 패키지를 실행한 것이 아니다.
