# GPT Work에 넣을 시작 요청

`C:\Users\22\Desktop\maintain\Hwp_doc` 프로젝트에서 공문 작성 워크플로를 가상 업무 5건으로 시험하자.

프로젝트 `CLAUDE.md`, `.claude/skills/hwpx/SKILL.md` 정본 본문과 `docs/GPT-공통실행기.md`를 먼저 읽어라. 실제 읽은 경로와 SHA256을 기록하고, git의 기존 미완료 변경을 확인해 보존하라. 이번 작업은 평가 세트 실행이며 스킬·실행기·훅을 고치는 작업은 아니다.

`evals/workflow_5/cases/01_notice.md`, `02_reply.md`, `03_capacity.md`, `04_budget.md`, `05_w2.md`를 순서대로 실행하라. **각 사례 최초 답변 전에는 suite.json·OPERATOR.md·rubric.json과 생성된 평가 기록의 판정 항목을 읽지 마라.** `evaluate.py`는 기록 생성/사후 집계용으로 실행할 수 있다. 초기화 출력은 횟수만 보여 준다. 각 사례의 원문 입력은 `cases/`의 해당 파일이다.

먼저 실제 앱이 ChatGPT Work인지, 로컬 작업인지와 파일·Python312·한글 COM·필요 MCP 접근 가능 여부를 확인하고 관측 가능한 앱/엔진 버전·모델·추론 설정을 기록하라. 알 수 없는 값은 미확인으로 남겨라. Codex/소프트웨어 시험을 Work 시험으로 표시하지 마라. 기존 보호 훅 문제를 이번 평가 통과로 해소됐다고 주장하지 마라.

새 실행 폴더를 `.claude/scratchpad/workflow-evals/` 아래에 만들고 `evaluate.py init --run-dir <새 폴더>`로 미실행 기록을 준비하라. 이미 있는 폴더/결과는 덮어쓰지 마라. 최초 참조 원본의 SHA256과 지침·스킬·실행기 버전을 저장하라. 매 단계의 대화·도구 원시 출력·시각·명령·실패/미확인 이유를 기록해 사후 판정에서 찾을 수 있게 하라. 생성 검토본은 output에 저장하고 OneDrive에 자동 복사하지 않는다.

01 입력부터 업무 근거 조회와 초안을 준비해 보여 줘. 사용자에게 꼭 필요한 값·구조 변경 판단·초안 확인이 있으면 구체적인 내용을 제시한 뒤 응답을 기다려라. 첫 요청을 초안 승인으로 간주하지 마라. 다른 회차 중 독립적으로 준비 가능한 탐색은 이어갈 수 있다. 임의 값, 합성 사용자 승인, 가짜 원문 조회·COM 통과 기록을 만들지 마라.

실제 사용자 확인 뒤 HWPX를 생성하고 전체 Validator와 복사까지 수행하라. 같은 단계가 2회 실패하면 그 단계의 자동 시도를 중단하고 증거와 다음 조치를 알려라. 다른 사례는 그 실패와 독립적이면 이어갈 수 있다. 생성한 최종본의 파일명에 eval-회차를 넣고 평가용 가상 문서·미발송으로 보고하라.

첫 중간 답변을 보존한 뒤에만 해당 사례를 기준표와 대조해 사후 점검하라. 판단 통과, 문서 검증 완료, 사람 동의 횟수는 구분해서 보고하라. 후속 응답과 초안 확인을 포함해 5건을 진행하되, 없는 원문/값은 끝까지 미확인으로 남겨라. 사람 평점은 내가 답한 점수만 기록하라. 평가용 결과를 실무 검토 로그나 기존 36회 인수에 자동 합산하지 마라.
