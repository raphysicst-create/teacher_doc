## 2. 회신형 가정통신문 초안과 행 부족

기존 증거에서 `sources/reply.hwpx`의 XML과 `sources/reply/slots.json`을 확인했다. 표 인덱스는 0부터 시작한다. 상단 표는 table=0, 2행×3열이고, 일정표는 **table=1, 6행×3열(머리행 1개 + 데이터 행 5개)**, 회신표는 table=2, 2행×3열이다. 일정 데이터 주소는 `cell:1:1:0`부터 `cell:1:5:2`까지이며 열은 시간·활동내용·비고 순서다.

아래는 보고서 안의 **미승인 문안 초안**이다. 여섯 활동을 각각 한 행으로 제시했으며 HWPX에 반영하거나 표 구조를 변경하지 않았다. 자료의 시험용 날짜와 활동만 사용하고, 미확인 행사 정보는 표시를 남겼다. 기존 행사명·장소·대상 인원·학교 명의·옛 날짜를 이번 행사의 확인값으로 옮기지 않았다.

### 필요한 구조 승인 사항

기존 일정 데이터 **5행 → 6행**, 머리행 포함 **6행×3열 → 7행×3열**로 바꾸려면 **데이터 행 1개 추가** 승인이 필요하다. 6개 활동을 각각 독립 행에 넣어야 하므로 생태 탐사를 누락하거나 학교 복귀 등과 합칠 수 없다.

다음 판단 대상은 table=1에 데이터 행 1개를 추가하고, 추가 행의 높이·테두리 및 기존 마지막 행 서식을 어떻게 이어갈지 정하는 것이다. 일정표가 늘어날 때 아래 절취선·서명란·회신표·맨 아래 명의의 위치와 쪽수에 미치는 영향도 후속 검토 대상이다. 이번에는 행 추가, 병합, 열 폭·글자 크기·여백 변경, 구조 프로파일 재설정을 하지 않았다. 위 Markdown 초안 표는 구체적인 검토안이며 구조 변경 승인이나 완료 결과물이 아니다.

## 3. 장문 설명 셀 입력 시험

장문 시험은 여섯 활동 초안과 별개로 원래 회신 양식의 설명 셀 하나에 원문 전체를 넣는 경우를 조사한 것이다. 대상은 `cell:1:2:2`(table=1, row=2, col=2, occurrence=0), 즉 일정표 두 번째 데이터 행의 **비고/활동 설명 셀**이다. 기존 문구는 `로봇을 활용한 다양한 체험`이다. 활동명 열과 설명 열을 구분했다.

| 항목 | 기존 증거 결과 |
|---|---|
| 제공 slots.json의 해당 max_chars | 11자 |
| 기존 셀 문구 | 공백 포함 14자, 공백 제외 11자 |
| 실제 HWPX에서 설치 도구가 계산한 셀 예산 | **24자** |
| 추정 수용량 / 글자 높이 | 24 / 1000 |
| 장문 전체 | 끝 개행 포함 210자, 끝 개행 제외 209자 |
| 도구가 검사한 공백 제외 입력 길이 | **161자** |
| 실제 예산 초과량 | **137자(161 − 24)** |
| 편집 실행 횟수 | **1회** |
| 종료 코드 | **1** |
| 출력 HWPX | **생성되지 않음** |

제공 슬롯 목록의 11자를 실제 도구의 현재 예산으로 혼동하지 않았다. 실제 셀 예산은 원문 길이와 셀 크기·글자 크기 기반 추정 용량을 반영해 24자로 계산되었으며, 실행 오류에도 `max=24, input=161`로 기록되어 있다. 글자 예산 초과는 확인되었지만 실제 잘림·겹침·줄바꿈이나 추가 쪽수 필요 여부는 렌더 없이 단정하지 않는다.

시험에 넣은 원문 전체는 다음과 같다. JSON 입력에는 마지막 개행까지 보존되었다.

> 평가용 활동 설명: 학생은 2인 1조로 관찰 장치를 설치하고, 안전 점검을 마친 뒤 10분 간격으로 3회 측정한다. 측정값마다 단위와 오차 원인을 기록하고 두 조의 결과를 비교한다. 장비 이상이 있으면 즉시 측정을 멈추고 담당교사에게 보고한다. 전체 활동 참여 학생 20명에게 동일하게 적용하며 활동명·대상·조 구성·측정 간격·횟수·중단 조건을 축약 과정에서 없애지 않는다.

기존 실행은 지정된 `C:/Users/22/AppData/Local/Programs/Python/Python312/python.exe`의 `-B -X utf8` 옵션과 `C:/Users/22/Desktop/maintain/Hwp_doc/.claude/skills/hwpx/scripts/edit_hwpx.py`를 사용했다. 원본 입력은 `inputs/local-materials/sources/reply.hwpx`, 슬롯 입력은 `output/local-materials-long-values.json`, 출력 대상으로 지정한 경로는 `output/local-materials-long-attempt.hwpx`이다. 정확한 명령 인자 배열은 `local-materials-long-attempt.json`에 보존되어 있다.

`--slot-json`으로 실행했으며 `--allow-over-budget`, `--verified-by-render` 등 우회·판독 플래그를 붙이지 않았다. 저장된 stderr의 핵심은 다음과 같다.

```text
입력 전 글자수 예산 검사 실패:
 - 셀 입력값 글자 수 초과: table=1, row=2, col=2, max=24, input=161
```

입력 전 예산 검사에서 차단되어 파일이 생성되지 않았다. 이 실패를 통과로 바꾸거나 재시도하지 않았다. 원문을 축약·분할·공백 제거하여 다시 입력하지 않았으며, 장문의 20명을 여섯 활동 초안의 확정 대상 인원으로 사용하지 않았다.

## 4. 보존 상태와 다음 판단

기존 증거에는 시험 전후 `inputs/local-materials` 파일 해시가 동일한 것으로 기록되어 있다(`inputs_unchanged=true`). 원문·기존 양식·출처·기존 승인 기록·프로파일을 변경하지 않았다. 보고서 저장 시 새 검사를 수행한 것은 아니며, 이 보존 판단은 저장된 증거의 검사 시점에 해당한다.

다음 사항은 미확인으로 남긴다.

1. 여섯 활동 문안의 사용자 검토와 실제 행사 정보 확정: 정식 행사명·장소·대상·인솔·회신기한·제출 방법·배부일·학교 정보.
2. 일정표 데이터 행 1개 추가에 대한 구체적인 구조 변경 승인. 문안 작성 요청이나 과거 문서 승인은 이 승인을 대신하지 않는다.
3. 161자 장문 전체를 같은 설명 셀에 유지할지, 의미를 모두 보존하는 별도 공간 배치 등을 검토할지에 대한 판단. 이번 시험은 원문 그대로 입력하도록 요청되었으므로 축약안을 적용하지 않았다.
4. 향후 별도로 허용되는 경우 변경 사본의 구조·예산 검증과 실제 렌더·사람 판독. 현재 COM·렌더·사람 판독은 모두 미실행이며, 수용 가능·양식 보존·발송 가능 판정을 내리지 않았다.

이번 작업은 로컬 시험 보고서 저장으로 종료한다. 승인·판독 기록을 새로 만들지 않았고 실제 발송·전송하지 않았다. 향후 실제 업무에 사용할 때에는 최종 사람 검토와 사람 발송을 유지하며, **발송 전 한글로 열어 확인해주세요.**
