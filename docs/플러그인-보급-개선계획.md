## 목적과 확정 범위

현재 업무 도구의 동작을 유지하면서, 동료 교사가 자기 학교 양식으로 공문을 작성하고 검증할 수 있도록 플러그인으로 보급한다. 핵심 경험은 자기 양식 등록 → 내용 교체 → 검증 → 사람 검토다.

- 첫 지원 환경은 Windows + 한글의 로컬 실행이다. Claude Code와 Codex는 각각 지원·시험한다.
- 두 앱 동시 실행, 실시간 상태 공유, 여러 앱·작업 폴더를 아우르는 COM 공유 잠금 확장은 범위에 넣지 않는다.
- 현재 COM 직렬 처리와 잠금은 유지한다.
- Mac 지원은 별도 시험 전까지 약속하지 않는다.
- 기존 슬롯 양식 5종, 사용자 양식 등록, W2·비정형 문서의 기존 생성 후 공통 검증 경로를 유지한다.
- 원본 보존, 미확인 값 유지, 실제 사용자 승인, 최종 사람 검토·사람 발송 원칙을 유지한다.
- 이 문서는 개선 계획이며, 현재 실행 규칙의 정본인 프로젝트 CLAUDE.md와 hwpx 스킬을 즉시 대체하지 않는다. 구현 후 확정된 동작을 해당 지침과 사용 안내에 반영한다.

## 2. 코드·작업 공간·PC 환경 분리

경로와 설정을 해석하는 공통 모듈을 만들고 실행기·조회 도구·훅에서 사용한다.

| 위치 | 저장 내용 |
|---|---|
| 플러그인 설치 폴더 | 코드·공통 지침·배포 기본 자료 |
| 교사의 작업 폴더 | 학교 설정·원본·등록 양식·승인 기록·검증 보고서·로그·산출물 |
| `%LOCALAPPDATA%\hwpdoc\` | PC별 Python 설정·의존성·재생성 가능한 캐시 |

PC별 데이터 폴더의 목적은 플러그인 업데이트와 무관하게 실행 환경을 보존하는 것이다. 앱 간 동시 실행을 위한 공유 상태 저장소로 확장하지 않는다.

- 학교명·문서번호 접두어·학년도·시간표 매핑·학교별 선호는 작업 폴더 설정으로 옮긴다.
- Python 경로는 PC 설정으로 관리한다. doctor는 고정 경로 일치 대신 버전·패키지·실행 가능 여부를 검사한다.
- 외부 복사 위치는 선택 설정으로 둔다. 현재 학교의 OneDrive 동시 복사 정책은 보존한다.
- 작업·양식 기록은 작업 폴더 기준 상대경로로 저장하고, 배포 양식은 식별자·버전·해시로 참조한다.
- 외부 원문은 작업용 사본으로 가져오고 출처를 기록한다.
- 기존 작업 기록은 호환해서 읽는다. 경로 이관 때문에 승인 해시를 임의로 다시 만들거나 과거 검증을 새 검증으로 처리하지 않는다.
- 기존 프로젝트는 현재 명령으로 계속 동작하도록 호환 경로를 유지한다. 배포본에는 현재 사용자·학교의 절대경로를 넣지 않는다.
- 기존 COM 직렬 처리와 잠금은 유지한다. 여러 앱·작업 폴더를 아우르는 잠금으로 확장하지 않는다.

학교 자료도 설정에서 선택하도록 바꾼다.

- 시간표 파일명·학년/반·교시·엑셀 위치와 관련번호 접두어를 코드에서 분리한다.
- 기존 시간표·사업관리카드 형식을 첫 지원 형식으로 문서화한다. 다른 형식을 임의 추정하지 않는다.
- 자료가 없으면 설치 전체를 막지 않고 해당 업무에서 요청한다.
- school_task_guide 연결은 선택할 수 있지만 업무 근거 확인은 유지한다. 미연결 시 원문 확인 경로와 미확인 상태를 사용한다.

**완료 기준:** 다른 사용자명·학교 설정·폴더 위치에서도 동작하고, 현재 학교의 업무 결과가 유지된다.

## 3. 기존 5종 이관 후 사용자 양식 등록 도입

등록제로 전환하기 전에 기존 슬롯 양식 5종을 새 등록 형식으로 옮긴다.

- 현재 파일·해시·슬롯·기준 파일·출처를 수집해 등록 초안을 만든다.
- 사람이 등록 정보를 확인한 뒤 전환한다. 전환 완료 전까지 기존 선택 경로를 유지한다.
- 하나의 양식에 여러 문서 용도를 연결할 수 있도록 한다. 양식 배치와 업무 유형은 별도로 관리한다.
- 기안문 공통 베이스와 승인본의 실제 파일을 대조해 제목 굵기·여백·붙임 구성 등 계보를 확인한다.
- 메모리 기록만으로 용도나 등록 완료 상태를 자동 확정하지 않는다. 메모리에 언급된 승인본 8건은 실제 파일 대조가 필요하다.

기존 build / validate / deliver / status를 유지하고 다음 기능을 추가·보강한다.

| 명령 | 역할 |
|---|---|
| init | 작업 폴더·설정·선택한 앱의 안내 지침 초기화 |
| add-template | 양식 사본에서 슬롯·의미 매핑·기준 파일·등록 초안 생성 |
| list-templates | 등록 상태와 지원 용도 표시 |
| prepare | 작업 입력과 기계적으로 수집 가능한 기록 준비 |
| doctor | 설치·작업 공간·한글·의존성·연결 상태 진단 |

양식 등록 순서는 원본 보존 → 슬롯·의미 확인 → 사본 finalize → 기준 생성 → 한글 및 필요한 시각 검토 → 등록 완료로 고정한다. 필수 파일·해시·등록 상태가 맞는 양식을 사용 가능 목록에 표시하고, 불완전하거나 변경된 양식은 구분한다.

prepare는 경로·해시·시각·환경 정보·슬롯 추출 결과를 수집한다. 사용자 승인·근거 해석·육안 판독을 대신 만들어 넣지는 않는다. 사용자에게는 누락된 값과 판단할 항목을 묶어서 보여준다.

**완료 기준:** 기존 5종을 계속 사용할 수 있고, 교사가 자기 양식을 등록해 복잡한 입력 파일을 직접 작성하지 않고 문서를 만들 수 있다.

## 4. 지침·메모리 정리와 앱별 진입점 마련

CLAUDE.md와 프로젝트 메모리·양식 README·실제 승인본을 함께 검토한다.

- 공통 업무 규칙은 배포 스킬과 참고자료로 옮긴다.
- 학교 선호는 학교 설정으로, PC 환경 정보는 doctor로 분리한다.
- 사례·추정·미승인 제안은 확정 규칙과 구분한다.
- 기계화된 검증 순서는 실행기 호출로 줄인다.
- 근거 해석·구조 변경 승인·육안 판독·최종 사람 검토는 지침에 남긴다.
- W1·W2 별도 스킬은 복원하지 않는다. 배포 스킬이 업무 절차를 명시적으로 읽도록 연결해 CLAUDE.md로 위임만 하고 끝나는 상태를 없앤다.
- 빈 셀 자동 검사 금지, 미응시 학년 행·열은 사용자가 직접 삭제, 운영 문서의 content.hpf 메타데이터 갱신 불필요 등 기존 사용자 결정을 보존한다.

init에서 사용할 앱을 선택한다.

- Claude Code를 선택하면 새 작업 폴더에 짧은 CLAUDE.md를 준비한다.
- Codex를 선택하면 짧은 AGENTS.md를 준비한다.
- 두 안내문은 같은 정본에서 생성하고, 설치 절대경로 대신 해당 앱에서 확인한 스킬 이름을 안내한다.
- 기존 지침이 있으면 덮어쓰지 않고 추가할 내용을 제시한다.
- 현재 maintain 부모와 Hwp_doc의 기존 fallback 구성에는 새 AGENTS.md를 만들지 않는다.

**완료 기준:** 사용자 전역 설정과 기존 메모리가 없는 환경에서도 선택한 앱이 업무 절차 본문을 실제로 읽는다. 스킬 목록 노출만으로 완료 판정하지 않는다.

## 5. 선택한 앱의 연결·훅 보호 검증

공통 보호 판정은 유지하고, 앱별 이벤트를 연결하는 부분을 구분한다. Claude Code와 Codex는 각각 독립적으로 시험한다.

시험 대상:

- Claude의 Write/Edit·Bash·실제 PowerShell 도구
- Codex의 패치·셸 도구
- 각 앱의 MCP 파일 쓰기
- 플러그인 설치 후 실제 이름으로 노출된 kordoc 도구
- 기존 파일 수정·삭제·이동·혼합 작업
- 정상 읽기와 새 사본 생성

도구 이름과 이벤트 형식은 실제 호출에서 확인한다. 일반 MCP 이름이나 다른 앱의 이벤트 이름을 그대로 적용하지 않는다.

- 공문 작업 폴더 표시와 정규화된 대상 경로를 함께 확인한다.
- 다른 프로젝트의 docs·knowledge를 이름만 보고 막지 않는다.
- 훅은 PC 설정에서 Python을 찾아 -X utf8로 실행한다. Python을 찾는 초기 실행 단계는 Windows 기본 실행 도구를 이용한다.
- Python 부재나 훅 실행 실패를 정상 보호로 표시하지 않는다.
- Codex 설치에서는 환경에 맞는 등록과 신뢰 확인 절차를 안내한다.
- 등록·신뢰·실제 차단 성공을 구분한다.
- Stop의 재시도 제한을 유지하고 빠른 종료 검사를 전체 검증으로 대체하지 않는다.
- 실제 운영 원본은 보호 시험에 사용하지 않는다. 동적 셸 쓰기 등 확인하지 못한 범위는 미지원·미검증으로 보존한다.

**완료 기준:** 앱별 보호 범위가 실제 시험으로 확인되고, 정상 업무의 오차단과 미지원 경로가 명시된다.

## 6. 배포본·의존성·업데이트 정비

- 허용 목록으로 별도 배포본을 만든다. 기존 저장소에서 운영 자료를 삭제해 공개본으로 바꾸지 않는다.
- 실제 공문·감사 로그·메모리 원문·임시 파일은 포함하지 않는다.
- 배포 자료의 학교 식별 정보는 본문·미리보기·메타데이터·이미지까지 확인한다. 운영 문서의 메타데이터 정책과 배포용 익명화를 구분한다.
- 업스트림 코드·의존성·포함 자산의 버전·출처·라이선스를 확인한다. 허용 조건이 확인되지 않은 파일은 배포에 넣지 않는다.
- 기본 Python 의존성과 Windows COM 의존성을 구분한다. PyMuPDF를 포함한 의존성도 라이선스 검토 대상이다.
- Node.js·kordoc은 선택 의존성으로 명시하고 미설치 시 대체 경로와 미사용 표시를 유지한다.
- 검증한 패키지 버전을 고정하고 플러그인·설정·양식 등록 형식의 버전과 변경 이력을 관리한다.
- 설치·업데이트·제거가 교사의 작업 자료를 삭제하지 않도록 한다.
- 운영용 폴백은 보존한다. 배포본에서 제외한다면 오류 안내와 복구 경로도 실제 지원 범위에 맞춘다.

**완료 기준:** 실행 환경을 재현할 수 있고, 업데이트·제거 후에도 교사의 자료와 작업 기록이 남는다.

## 7. 동료 PC 시범 사용과 성능 개선

첫 지원 범위는 Windows + 한글에서 Claude Code 또는 Codex 사용이다. Mac 지원과 두 앱 동시 실행 시험은 포함하지 않는다.

새 계정이나 동료 PC에서 다음을 시험한다. 새 계정 생성은 이 계획 문서 저장 작업에 포함하지 않는다.

- 한글 보안모듈 미등록 상태의 진단·안내
- 한글·공백·260자 초과 경로
- 기존 5종과 새 학교 양식 등록
- W2 제출 방법 미확인·업무 근거 연결 실패
- 행 부족·긴 문구·복사 잔재
- 원본 보존·승인 후 입력 변경
- 외부 복사 실패 후 재시도
- 업데이트 후 작업 계속하기

지원하지 못하는 조건은 사전에 안내한다. 기본 검사는 구조·내용·레이아웃 위험을 확인하며, 실제 한글 쪽수·잘림 검증과 구분한다. COM·필수 렌더 불가 상태를 통과로 바꾸지 않는다.

먼저 동료 교사 한 명이 설치 → 자기 양식 등록 → 작성 → 한글 검토 → 업데이트를 마치도록 한다. 선택한 앱의 시범 사용과 별도로, 보급 대상으로 표시하는 각 앱의 독립 인수 증거를 확보한다.

성능은 단계별 시간을 측정한 후 개선한다. 실제 참조 자료와 검색 인덱스 버전을 추적해 무관한 자료 변경으로 인한 재검증을 줄이고, 안전한 캐시부터 적용한다. 최종 파일이 바뀌면 검증을 다시 수행한다. 복사 실패는 복사만 재시도하는 현재 동작을 유지한다. 승인·검증 의미가 바뀌는 최적화는 첫 배포에 넣지 않는다.

**최종 보급 기준:** 원본 훼손·값 날조·승인 조작·실패의 통과 보고가 없고, 교사가 미확인 사항과 다음 행동을 이해할 수 있다.
