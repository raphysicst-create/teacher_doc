# 업무 지침 조회 연결

`school_task_guide`는 전국 공통·시도교육청 지침의 근거 조회 서버다. 개별 학교 지침을 이 서버에 등록하지 않는다. Hwp_doc의 실제 공문·개별 사업자료는 기존 폴더에서 읽고 해당 업무에 한정해 대조한다.

Codex 프로젝트 설정은 `.codex/config.toml`, Claude 설정은 `.mcp.json`이다. 기존 kordoc 항목을 보존했다. 고정 Python3.12와 서버의 격리 의존성으로 실행하며 전역 설정·패키지는 바꾸지 않는다. Codex의 프로젝트 MCP 구성 방식은 [공식 MCP 문서](https://learn.chatgpt.com/ko-KR/docs/extend/mcp)에 따른다.

## 호출 순서

1. W1 유사 공문·양식 탐색 후, W2 수신 공문 분석 후 실제 업무 설명을 `find_tasks`에 전달한다.
2. 선택한 업무와 확인된 지역·학교급·설립구분·적용일·학년도/회계연도만 `get_task_guide`에 전달한다. 학교명·실명·추정 조건은 보내지 않는다.
3. 심의·동의·안전·예산처럼 구체적인 질문을 `search_task_evidence`로 검색하고 선택한 근거 ID를 `read_evidence`로 읽는다. 표·주석·계속 쪽과 응답의 다음 커서를 끝까지 확인한다. `find_tasks.limit`은 최대 10, `search_task_evidence.limit`은 최대 20이며 기본값을 우선 사용한다. `read_evidence`는 한 번에 ID 5개 이하로 나누어 호출한다.
4. 작성할 문구와 별도 수행할 행정 절차를 구분한다. `partial`·`pending_items`·미확인 적용기간 및 최신판 사유는 그대로 검토 기록에 남긴다.
5. 보조사업 교부 조건·별도 상급기관 공문 등 구체적 근거가 있으면 Hwp_doc의 해당 원문을 대조한다. 사업자료가 조회 서버에 등록되어 있다고 추정하거나 일반 단가가 모든 사업에 우선한다고 판단하지 않는다.
6. 확인 결과를 초안에 반영하고 기존 시간표·예산명·관련번호 도구와 HWPX 생성·검증을 수행한다. 발송과 최종 결재는 사람이 한다.

## 연결 확인

프로젝트에서 `codex mcp get school_task_guide --json`으로 설정 인식을 확인한다. 현재 실행 중인 클라이언트에서 도구가 보이지 않으면 다음 연결 로드 후 네 도구의 노출·호출을 확인한다. 별도 SDK의 서버 검증, 실제 Codex CLI 호출, 현재 데스크톱 세션의 도구 노출은 다른 확인 항목이다.

등록 지침의 공식 최신판·효력기간 확인이 남아 있으면 사람이 검토한 안내도 `partial`일 수 있다. 숫자만 복사해 확정 기준으로 쓰지 말고 반환 사유와 원문을 함께 검토한다.

## 첫 사례

2026학년도 농어촌유학 수리과학체험 계획(5650)을 실제 사례로 사용한다. 입력은 기존 결재본의 행사일·대상·예산이며 새 행사값으로 바꾸지 않는다. 조회·검증 기록과 보완사항은 `output/`의 별도 검토 결과에 저장한다. 원본 계획은 보존하고, 문서에서 찾을 수 없는 행정 절차를 실제 미이행으로 단정하지 않는다.
