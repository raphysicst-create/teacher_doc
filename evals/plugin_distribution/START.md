# 독립 평가 세션 시작 지시

Hwp_doc의 evals/plugin_distribution/을 사용해 플러그인 보급 개선 계획 전체를 독립 평가한다. 이 지시는 **평가 요청을 받은 별도 세션**이 사용한다. 설계/구현 세션은 실제 평가를 대신하지 않는다.

1. README.md, OPERATOR.md, AGREEMENT.md, CONTRACT.md, FIXTURES.md를 읽는다. 구현 세션은 사용자의 별도 지시로 작업을 재개했으므로 현재 후보를 확인한다. 기능이 없으면 제품 코드를 고치지 말고 pending 또는 실제 명세 위반을 기록한다.
2. git status와 실제 구현/배포 후보 파일을 확인하고, HEAD·diff·미추적 파일 목록·모든 대상 파일 해시를 동결한다. 자료 범위는 허용 목록에 적고, 개발 작업이 계속 바뀌면 안정된 평가 사본을 요청한다.
3. 본인의 실제 세션 ID로 장부를 초기화한다. 코드·양식·fixture·평가 기준이 바뀌면 기존 통과를 그대로 쓰지 않는다. 집계기의 stale를 없애려고 lock.json을 재작성하지 않는다.
4. 실제 앱·버전·모델/effort·도구 이름을 관측대로 적는다. CLI/모의 이벤트를 Claude/Codex 실제 앱 증거로 바꾸지 않는다. 한 앱만 사용할 수 있으면 그 앱부터 평가하고 다른 앱 행은 pending/blocked로 둔다. 동시 실행은 시험하지 않는다.
5. FIXTURES.md에 따라 평가용 자료 사본과 필수 사람 입력을 준비한다. 실무 원본을 변조하거나 운영 설정·레지스트리·전역 훅·실제 플러그인을 시험 목적으로 바꾸지 않는다. 별도 격리 환경이 없으면 해당 행은 blocked다.
6. 각 평가 행의 cases/ 입력을 먼저 수행하고 최초 출력·도구 기록을 고정한 뒤 해당 rubrics/와 대조한다. 평가 대상에게 판정표/기대 답을 먼저 전달하지 않는다. 이미 기준을 읽었다면 노출 사실을 기록하고 새 문맥에서 최초 수행을 확보한다.
7. 사람의 초안 승인·구조 변경·등록 확인·시각 판독·최종 검토가 필요한 곳은 실제 응답을 기다린다. 평가 에이전트가 사람 역할로 답하거나 승인 JSON을 조작하지 않는다. CLI 연결 시험 합성 입력은 명시하고 실호스트·사람 실적에 넣지 않는다.
8. 각 행의 필수 증거 파일, SHA256, 위치(locator), 평가자 확인을 기록하고 evaluate.py score로 누락을 점검한다. 기대되는 안전한 거절은 동작 pass일 수 있지만 문서 검증·전달·사람 동의와 분리한다.
9. 결과를 단계·앱·variant별로 보고한다. 실패 위치와 재현 자료, 미구현/환경 부재, release_ready를 구분한다. 실무 발송·배포·푸시·다른 세션 생성은 이 지시에서 자동 수행하지 않는다.

시작 답변에는 평가 가능한 범위·현재 미구현/환경 제약·동결할 후보를 짧게 밝힌다. 실제 평가는 사용자가 지정한 별도 세션에서 수행하며 제품 구현이나 기준 수정으로 실패를 없애지 않는다.
