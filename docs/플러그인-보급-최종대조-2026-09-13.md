# 플러그인 보급 계획과 구현 대조

2026. 9. 13. · Hwp_doc · 기준 9f3baca

개선계획 원문을 보존하고 기존 구현결과·구현보완 보고서 이후의 변경을 기록한다. **전체 계획 완료나 보급 가능 상태를 선언하는 문서가 아니다.** 사용자 목표에서 외부 컴퓨터 시험은 제외됐지만, 실제 사람 확인·재배포 권리·앱 인수의 미확인을 통과로 바꾸지는 않았다.

## 이번 보완과 검증

- Python 실행 파일/버전/구현/아키텍처와 설치 패키지 버전을 보고서에 기록한다. 달라지거나 옛 보고서에 기록이 없으면 과거 검증은 미확인이다. 입력과 원문이 그대로일 때 validate가 실제 문안 승인과 manifest 해시를 보존하고 runtime_updates/tool_updates를 기록한 뒤 전체 검증을 다시 실행한다.
- doctor는 실제 import와 고정 패키지 버전을 대조한다. 잘못된 버전, 바이너리 import 오류, 선택 의존성 부재를 구분한다.
- 원본 content.hpf의 작성자·날짜와 proposal의 과거 사업 내용을 발견했다. 운영 원본은 수정하지 않고 distribution/assets에 별도 익명화 후보를 만들었다. proposal의 구조 지문은 동일하며 변경은 텍스트다. preparation.json의 출처·변환 해시는 허가 기록이 아니다.
- 배포 검사에서 채워진 작성자 메타데이터를 차단한다. 합성 권리 기록이 있어도 해당 차단이 유지되는 개발 시험을 추가했다. 패키지는 모든 복사 해시 확인 후 완성 위치로 옮긴다.
- 운영 폴백은 보존한다. 폴백이 없는 배포 설치에서는 존재하지 않는 도구를 실행하라고 안내하지 않고 한글 새 사본 저장/재생성 후 전체 검증을 안내한다.
- 개발 회귀시험 **89개 통과**, `git diff --check` 통과(줄바꿈 경고만 존재). 고정 Python312에서 실행했다. 별도 평가 패키지는 수정하거나 실행하지 않았다.

## 계획 항목별 근거와 남은 조건

| 단계 | 구현·확인 근거 | 완료로 처리하지 않은 조건 |
|---|---|---|
| 1. 기준 검수 | 기존 시험 유지, 같은 합성 입력의 편집/finalize 해시 동일성, 제목/여백/표 회귀, 승인본 8건 실제 파일 계보 대조 | 전체 COM/렌더의 개선 전후 운영 인수는 별도 평가 |
| 2. 환경 분리 | 공통 경로 설정, 상대경로 보고서, 학교 설정, PC runtime, 기존 학교/OneDrive 호환, 작업 폴더 COM 잠금, 격리 venv 설치 및 doctor | 다른 계정·PC와 260자 초과 경로 미검증. 외부 PC 시험은 사용자 제외 범위 |
| 3. 등록 | init/add-template/list-templates/migrate-templates/prepare, 원본/슬롯/의미/복수 용도/검토 해시, 합성 양식 COM/PDF/PNG 실동작 | 기존 5종의 새 등록 초안과 실제 사용자 양식에 대한 사람 확인. 확인 전 기존 경로 유지 |
| 4. 지침 | 공통 workflow 정본, 앱별 안내문, 기존 지침/학교 선호/사용자 결정 보존 | 메모리 없는 실제 앱이 본문을 읽은 증거 |
| 5. 훅 | 범위 판정, PC Python 부트스트랩, 소유 기록에 따른 등록/업데이트/제거, Stop 제한과 미확인 유지 | 실제 앱별 도구명·MCP 이벤트·신뢰·차단 및 오차단 인수. 합성 호출은 대체 증거가 아님 |
| 6. 배포 | 70파일 허용 목록, 고정 의존성 설치, 권리/개인정보 해시 차단, 익명화 후보, 업데이트 재검증, 자료 보존 제거 | 파일별 재배포 권리/개인정보 검토 70건 및 의존성 조건 8건 미확인. 설치 가능한 공개 패키지를 만들지 않음 |
| 7. 시범·성능 | 단계 시간 기록, 사용한 학교 자료만 의존성 추적, 최종 파일 변경 재검증, 외부 복사만 재시도 | 동료 PC 시범 사용 제외. 각 앱 독립 인수와 실측에 따른 추가 최적화는 미완료 |

기계 단계가 준비됐다는 사실과 계획의 인수 조건이 충족됐다는 사실을 구분한다. 위 조건을 없애거나 승인 기록을 만들어 넣어 목표를 닫지 않는다. 커밋·푸시·공개 배포·실제 앱 재설치는 하지 않았다.

## 이어서 필요한 입력·증거

1. 배포자 코드의 라이선스 선택과 업스트림/자산의 실제 재배포 허용 근거. 사용자 선택만으로 타인의 권리를 승인할 수는 없다.
2. 기존 5종 등록 초안의 실제 사람 확인. 원본·용도·매핑·현재 검토 파일을 확인한 기록으로만 전환한다.
3. 별도 평가 담당 작업의 실제 앱 인수 결과. 로컬 개발 테스트를 앱 증거로 입력하지 않는다.

이 문서는 앞선 69개/80개 시험 기록을 89개 개발 시험 결과로 보완하며, 기존 학교의 업무 승인 기록으로 복사하지 않는다.
