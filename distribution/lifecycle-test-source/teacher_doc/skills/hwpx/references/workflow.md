# 공문 작성·검토 업무 절차

이 문서는 플러그인에서 직접 읽는 공통 절차다. 학교 업무는 W1(신규), W2(회신)로 구분하되 스킬은 하나다. 기존 운영 프로젝트의 명시적인 사용자 결정은 그대로 적용한다. 메모리의 사례나 미승인 제안을 다른 학교의 확정 규칙으로 옮기지 않는다.

## 작업 공간과 시작

- 코드 루트의 `scripts/teacher_doc.ps1 --workspace <교사 작업 폴더> <명령>`을 사용한다. 기존 hwpdoc.ps1도 호환된다. 설치 폴더에는 작업 자료를 쓰지 않는다.
- 첫 사용은 `init <새 작업 폴더> --app claude|codex --skill-name <앱에서 확인한 스킬 이름>`이다. 기존 지침은 덮어쓰지 않는다. init은 스킬 실제 로딩이나 훅 신뢰·차단을 보증하지 않는다.
- `doctor`는 Python/의존성/한글/작업 폴더/학교 자료를 진단한다. 등록·신뢰·실제 호출 성공을 구분한다. PC 설정은 `%LOCALAPPDATA%/hwpdoc/runtime.json`, 학교 설정은 `.hwpdoc/workspace.json`이다.
- 학교 이름·문서번호 접두어·학년도·시간표 매핑·선호를 작업 설정에서 확인한다. 비어 있으면 필요한 업무 시점에 묻는다. 다른 학교의 값을 복사하지 않는다.
- 외부 원문은 작업용 사본으로 가져오고 출처와 해시를 남긴다. 암호화·DRM·배포용 문서는 우회하지 않는다. 민감한 개인정보를 발견하면 사용자에게 알리고 처리 방침을 확인한다.

## 양식 선택과 등록

1. 유사 공문과 사용자 지정 양식을 먼저 읽는다. 같은 문서의 변환본과 사람이 한글에서 저장한 최종본이 함께 있으면 후자를 고른다. 제목 강조·상단 여백·일정 상자·표 순서/병합·날짜/명의 위치를 초안부터 따른다.
2. `list-templates`에서 기존 5종 또는 등록 완료 양식을 고른다. 회신이 필요하면 참가·불참과 보호자 서명이 있는 회신형을 고른다. 양식 배치와 업무 용도를 구분하며 하나의 양식에 여러 용도를 연결할 수 있다.
3. 새 양식은 `add-template --id <이름> --version <버전> --source <HWPX> --purpose <용도>`로 원본 사본과 슬롯 목록을 만든다. 실제 추출 슬롯 주소를 읽어 의미→슬롯 JSON을 작성한다. 표의 n번째 행/열을 마크다운만 보고 추정하지 않는다.
4. 같은 명령의 `--mapping <JSON>`으로 사본 최종화·프로파일·한글 검사를 준비한다. 결과의 실패/미확인을 확인한다. `--review <JSON>`은 사용자가 실제 양식·매핑·용도·현재 해시를 확인한 기록을 받은 뒤에만 제출한다. 파일 존재나 confirmed 필드는 실제 사람 확인을 대신하지 않는다.
   `--review-draft`는 필요한 PDF/전체 페이지 PNG와 미승인 검토 기록을 준비한다. 생성한 PNG를 실제로 읽고 원본 양식과 대조한 뒤 확인할 내용을 사용자에게 보여준다. 기록 초안의 빈 승인/판독 필드를 기계 생성 성공으로 채우지 않는다.
5. 기존 5종의 `migrate-templates` 결과는 이관 조사 기록이다. 사람이 등록 정보를 확인하기 전에는 새 등록 완료로 선언하거나 기존 선택 경로를 제거하지 않는다. 과거 승인본 계보는 실제 파일을 대조하며 메모리만으로 확정하지 않는다.

## W1 신규

1. 유사 공문·선정한 양식의 경로와 보존할 배치를 기록한다. `prepare --job <이름> --document-type <유형> --template <이름> [--version <등록 버전>]`로 입력 준비를 시작할 수 있다. 이 명령은 승인이나 업무 판단을 생성하지 않는다.
2. 초안 전에 업무 근거를 확인한다. `school_task_guide`가 연결되면 `find_tasks → get_task_guide → search_task_evidence → read_evidence`로 원문 조건·예외·적용기간/최신판을 읽는다. 연결 실패·partial·pending_items를 기록하고 확인한 원문으로 대체한다. 미지원 업무는 원문 검색으로 진행한다. 미확인을 확정 의무로 바꾸지 않는다.
3. 시간표는 `fusion_timetable.py`, 예산 항목 이름은 `budget_name_check.py`, 관련번호는 `related_lookup.py`의 확인값만 쓴다. 별도 보조사업의 교부 조건은 원문을 대조하며 일반 단가로 임의 교체하지 않는다. 원문/자료가 없으면 질문하거나 placeholder로 남긴다.
4. 공유값은 한 소스에서 본문·붙임에 넣는다. 초안은 선정 양식을 따르고 사용자에게 보여준다. 사용자가 제시된 문안의 작성을 요청하면 문안 생성 승인으로 기록한다. 구조 변경은 구체적인 대상·변경 전후·이유와 그에 대한 사용자 원문을 따로 남긴다. 이미 승인한 같은 변경을 재질문하지 않는다.
5. 확인받은 입력과 초안의 해시를 기록한 뒤 build한다. 활동별 행이 부족하면 서로 다른 활동을 한 셀에 합치지 않는다. 새 작업번호로 실패 한도를 우회하거나 승인 해시를 임의로 재작성하지 않는다.

## W2 회신

1. 수신 원문에서 요지·요청사항·기한·제출 방법·문서번호·시행일을 읽는다.
2. 공문 회신 지정은 회신 시행문, 시스템/메일 제출은 내부결재로 분기한다. 제출 방법이 미확인이면 어느 쪽도 임의 선택하지 않는다.
3. 업무 근거 확인을 초안 전에 수행한다. 수신 문서번호·시행일을 원문 및 관련번호 조회로 대조한다. 결재일과 시행일을 혼동하지 않는다. 조회 실패면 원본/값을 요청한다.
4. W1의 값 수집·문안 확인·검증·검토 절차로 합류한다. 슬롯 경로로 표현할 수 없는 문서는 기존 생성 경로에서 새 HWPX를 만든 뒤 `validate --manifest`를 적용한다. 최종 보고에 회신기한을 남긴다.

## 문안과 기존 사용자 결정

- 날짜는 `2026. 9. 13.`, 시간은 `14:30`, 금액은 `금123,456원(금일십이만삼천사백오십육원)` 형식이다. 날짜-요일은 gonmun_lint 기계 검증을 사용한다.
- 항목부호는 `1. → 가. → 1) → 가) → (1) → (가) → ① → ㉮` 순서다. 마지막 본문 또는 붙임 표시 뒤 한 글자를 띄우고 `끝.`을 쓴다.
- 기안문 서체·크기는 학교 설정을 확인하고, 붙임은 선택한 양식을 따른다. 인솔/담당 표기는 실명 대신 직책과 인원을 우선하며 회의록 참석자 등 실명이 본질인 경우를 구분한다.
- 회신형 가통의 날짜·학교장 명의는 회신표까지 포함하여 맨 아래 둔다. 회신 기한은 본문에 안내하고 중복 각주를 만들지 않는다. 회신표 첫 열은 행사/장소를 식별하게 쓴다. 학교의 기존 결정이 적용되는 경우 회신 기한 기본은 행사 4일 전이다.
- 빈 셀 자동 검사는 만들지 않는다. 미응시 학년 등 행·열 전체 삭제는 사용자가 직접 하도록 안내한다. 운영 문서의 content.hpf 메타데이터는 갱신하지 않는다. 배포용 익명화는 별도 작업이다.

## 검증과 전달

`validate`의 전체 순서를 따른다: 구조 → namespaces → finalize(--strip-linesegarray) → layout → page_guard → 한글 COM 실열림 → 조건부 render/육안 판독 → content/values/gonmun → 예산명/관련번호/시간표/붙임 → 신구대조.

- Codex CLI에서 COM을 포함한 명령은 셸 도구의 `timeout_ms`를 명시한다(전체 검증은 300000). 기본 10초 종료를 COM 실패로 혼동하지 않는다. `exec_command`가 세션 ID를 반환하면 같은 세션을 기다리고 명령을 재실행하지 않는다. 실행기 내부의 단계별 시간 제한과 2회 실패 제한은 유지한다.
- `HANCOM_RESTRICTED_CONTEXT`는 Windows 제한 토큰·격리 데스크톱의 COM 미확인이다. 시간만 늘리거나 권한 설정을 자동 변경하지 않는다. 한글·보안 모듈이 설치된 사용자 세션에서 검증하고 실제 환경을 보고한다. 한 환경의 통과를 다른 권한 모드의 통과로 기록하지 않는다.

- 프로파일은 finalize가 끝난 기준 사본에서만 생성한다. 검사 실패를 없애려고 결과물로 기준을 다시 만들지 않는다. 구조 변경 승인이 있을 때만 승인 범위·원본 크기/쪽수·COM/렌더 결과를 대조하고 새 기준을 만든다.
- 변환본·재패키징 베이스 편집은 render_check를 통과해야 한다. 예산 초과 셀은 PDF→PNG를 실제로 보고 현재 최종 파일 해시와 연결한 판독 기록을 남긴다. 플래그는 셀 폭을 늘려주지 않는다.
- 기존 문서를 재사용할 때 이전 문서의 고유 명칭과 옛 날짜를 content_rules.forbid에 모두 넣는다. 비어 있으면 이유를 기록한다. 이름·수치·조건을 훼손하는 축약은 사용자에게 판단을 요청한다.
- 같은 단계가 2회 실패하면 자동 시도를 중단하고 이력을 보고한다. 운영 환경의 폴백이 실제 설치돼 있으면 기존 F/A 재생성 후 strict와 주력 전체 검증을 수행한다. 폴백이 배포본에 없으면 설치된 것처럼 호출/완료 처리하지 말고 한글 네이티브 사본 저장 또는 수동 복구 경로를 안내한다.
- kordoc이 없으면 HWPX는 text_extract, 슬롯/셀은 edit_hwpx, diff는 추출 텍스트 대조로 대체하고 미사용 사실을 기록한다. .hwp 편집 베이스는 한글 COM으로 HWPX 사본 저장을 우선하고 변환 사실을 알린다. .hwp 결과물은 생성하지 않는다.
- 최종 파일 변경은 재검증 대상이다. COM·필수 렌더 불가, 업무 근거 미확인, placeholder는 완료로 바꾸지 않는다. Stop의 빠른 검사는 전체 검증을 대신하지 않는다.
- `deliver`는 output과 설정된 외부 복사 위치에 검토본·보고서를 저장한다. 외부 복사 실패는 복사만 재시도한다. 미확인 문서는 `deliver --draft`로 명확히 표시한다. 최종 사람 검토와 사람 발송을 유지하며 **발송 전 한글로 열어 확인해주세요**를 안내한다.
- 사용자가 동의 여부와 5점 평가를 알려주면 작업 폴더의 검토 로그에 기록한다. 평가 실험 결과를 실제 업무 검토 로그로 섞지 않는다.
