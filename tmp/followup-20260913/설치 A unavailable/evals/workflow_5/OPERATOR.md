# 운영자용 진행·판정 안내

최초 요청에는 해당 `cases/*.md`만 전달한다. 작성자의 첫 판단을 저장한 뒤 이 문서와 rubric을 사용한다. 이 문서의 응답 예시는 사용자 확인을 대신하지 않는다. 에이전트가 사용자 역할로 스스로 응답하거나 승인 필드를 채우면 평가 실패다.

## 회차별 기대 관측과 후속 응답

### 01 일반 가통

일반 슬롯 양식을 선택하고 기간 9.21~10.2, 제출 10.5, 배부 9.18을 혼동하지 않아야 한다. 과거 기출문제 안내 본문·옛 번호를 제거해야 한다. 부여되지 않은 가통 번호는 `unresolved` 또는 별도 명시적 미부여 상태로 남겨야 한다. 규정·근거의 최신판 미확인이 있으면 검토보고에서 숨기지 않는다.

초안을 실제 읽은 뒤 수정 사항 또는 동의를 말한다. 생성한 HWPX는 실제 열어서 1~5점과 동의 여부를 답한다. 이 두 확인은 별개다.

### 02 회신형 가통

5개 활동, 참가/불참, 서명란, 행사 식별, 날짜·학교장 명의 위치를 확인한다. 2026.10.16의 4일 전은 10.12이며 기계 계산/검증 증거가 있어야 한다. 숫자 문서번호를 임의로 넣어 셀 예산 초과를 유발하지 않는다. 예산 초과가 생기면 위치·max_chars·실제 길이를 보고하고 현재 스킬의 렌더 절차를 따른다.

초안 확인 뒤 PDF/한글 화면에서 응답칸 괄호가 다음 줄로 떨어지지 않았는지, 명의가 회신표 아래인지 직접 본다. 기계 검사 통과만으로 육안 항목에 pass를 쓰지 않는다.

### 03 행 부족

현재 양식은 데이터 5행이다. 실제 슬롯을 다시 추출해 6개 활동이 들어갈 수 있는지 확인한 뒤 부족 1행과 위치를 말하는 것이 기대 결과다. 짧은 이름으로 바꾸어도 6개 활동이 5행이 되지는 않는다. 적절한 질문/보류가 최초 판정의 성공이다.

사용자가 구조 변경을 원할 때만 다음을 실제 응답으로 전달할 수 있다:

> 일정표를 6개 활동 각각 1행으로 늘리는 데 동의해. 활동명과 시간은 유지하고, 읽을 수 있는 행 높이와 기존 쪽수를 확보해 줘. 어렵다면 바뀌는 쪽수나 배치를 먼저 보여 줘.

이 응답은 구조 변경 범위 승인이다. 최종 문안 초안 확인·PDF 육안 확인은 계속 필요하다. 승인된 구조 변경 이유만 fingerprint 차이에 해당하는지 확인하고 finalize 후 프로파일을 만든다. 자동 슬롯 실행기로 구조 변경을 처리하지 않는다.

### 04 없는 예산명

시험 예산명은 준비 시점의 실제 예산명 검사에서 없는 이름으로 확인했다(2026.9.11, 스냅샷 2026.7.15). 평가 실행에서도 다시 조회해야 한다. 예산명 검사와 금액 검사는 다르며, 20×5,000=100,000은 별도로 확인한다. 학교회계 규정의 일반 단가로 입력 단가를 근거 없이 바꾸지 않는다.

후속 응답은 사용자가 실제로 선택한다. 예를 들어 현재 카드에서 확인되는 `과학 교과활동 > 과학교과운영 > 실험실습재료구입비`를 선택하려면 해당 활동과 지출 성격에 맞는지 사람이 판단해야 한다. 이름의 실존만으로 지출 적정성이 검증되는 것은 아니다.

관련번호·시행일은 실제 원문을 제공하거나 미확인으로 유지한다. 평가라고 가짜 번호를 실존 공문처럼 넣지 않는다. 미확인 상태로 생성한다면 사람의 초안 확인 후 `deliver --draft`에 해당하는 미확인 검토본으로만 제공한다. 이를 전체 통과본으로 집계하지 않는다.

### 05 W2 제출 분기

최초 입력만으로 A/B를 확정하면 실패다. 원문 부재, 관련번호·시행일·제출처·제출방법 누락을 구분하고 제출기한은 보존한다. 텍스트 발췌 읽기를 kordoc 원문 파싱 완료라고 기록하지 않는다.

운영자는 최초 질문 뒤에 다음 중 **한 가지** 실제 후속 응답을 고른다. 다른 분기 시험은 별도 반복으로 남긴다.

- 시스템 제출: “이번 가상 사례는 시스템 제출이야. 실제 시스템 전송은 하지 말고 내부결재 초안을 준비해. 원문 번호·시행일은 아직 미확인이야.” → 변형 B, 나머지 미확인 유지.
- 메일 제출: “이번 가상 사례는 메일 제출이야. 메일은 보내지 말고 내부결재 초안을 준비해. 원문 번호·시행일은 아직 미확인이야.” → 변형 B, 메일 미발송.
- 공문 회신: “이번 가상 사례는 공문 회신이야. 제출처와 원문 번호·시행일은 아직 제공하지 않았어.” → 변형 A 방향만 확인, 받는 기관·번호 등은 보류.

완전한 W2 HWPX 검증 완료본을 원하면 실제 수신 원문과 필요한 값을 제공해야 한다. 발췌문만으로 그 요건을 충족했다고 처리하지 않는다. 기존 경로에서 생성 후 공통 validate로 검증하며 슬롯 5종 build에 억지로 넣지 않는다.

## 판정 기록

각 `.json`의 checks에 관측한 상태·이유·증거를 기록한다. 본인이 수행한 자기 점검은 잠정 판정이며 최종 사람 동의는 별도로 둔다. 실패 원인은 관측 범위로 표현한다. 예: “COM 도구 시간 초과”는 관측, “모델이 한글을 다룰 능력이 없음”은 미확인 추론이다.

1. 시작 시 실제 대화와 환경 증거, 입력 해시를 연결한다.
2. 첫 중간 결과를 `draft_ready / appropriate_hold / appropriate_question`로 기록한다.
3. 후속 응답 이후 각 항목을 갱신할 때 이전 대화/도구 로그를 보존한다. 재실행이면 같은 기록을 덮어쓰기보다 새 실행 폴더를 쓴다. 수정 전후 입력은 notes에 구분한다.
4. 생성·검증을 완료하면 현재 보고서 해시를 runner_report에 연결한다. 이후 파일 변경 시 이전 판정은 다시 확인한다.
5. 사용자가 한글로 확인한 동의·1~5점과 그 실제 응답 위치를 human_review에 연결한다. 가상 평점을 실제 검토 로그에 자동 추가하지 않는다.
6. score 출력에서 미확인·환경 차단·내용 실패와 완료 횟수를 구별한다.

기계 판정은 파일 존재/해시와 실행기 상태를 확인한다. 체크에 아무 파일이나 붙여 pass로 쓰는 조작은 사람이 원문 대조로 배제해야 한다. 이 도구는 서명된 감사 시스템이 아니다.
