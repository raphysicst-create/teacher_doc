# 기존 output/examples 자료 활용 시험

`output/`과 `knowledge/examples/`에 충분한 자료가 있었다. 이를 실물·검토 로그까지 대조하지 않고 34개 평가 행에 자료 부족 사유를 유지한 판단을 정정한다. 사용자 요청에 따라 기존 자료를 로컬 시험용 사본으로 연결하고 실제 검사를 진행했다.

## 찾아서 사용한 자료

두 폴더에서 HWPX 100개, PDF 69개, HWP 원본 1개를 확인했다. 이번에는 기안문 8건, 승인된 정산보고서 1건, HWP 원본 1건과 기존 승인 양식 3종을 선정했다. 선택한 13개 원본은 모두 수정 전후 해시가 같다.

| 자료 | 확인한 출처·용도 | 결과 |
|---|---|---|
| 2026년 2학기 기안문 8건 | output의 평가계획 수립·가통 안내·1/2회 고사 협의회·출제연수·가통 배부·기출문제 공개. review_log의 2026. 7. 18. 실제 승인과 대응 | 전부 공통 기안문 베이스의 header 해시·제목 스타일·페이지 여백과 동일. 각 1쪽으로 실제 한글 열림/PDF 내보내기 성공 |
| 일반 가정통신문 | examples 2348에서 승격된 기존 템플릿, 현재 5종 등록 승인 | 제목·안내 상자·하단 날짜/명의와 슬롯 실물 확보. 구조/렌더 통과 |
| 회신형 가정통신문 | 사용자가 한글에서 수정한 최종 v4를 승격한 기존 템플릿, 현재 5종 등록 승인 | 일정표 데이터 5행, 참가·불참/보호자 서명, 맨 아래 날짜/명의 확인. 구조/렌더 통과 |
| 공통 기안문 | 성립전예산요구 양식과 위 8건의 실물 | 같은 서식을 내부결재·가통 발송에 사용한 실제 근거 확보 |
| 실적·정산보고서 HWP 원본 | examples의 교육지원청 배포 서식 | kordoc 실제 읽기 성공. COM으로 HWPX 사본 저장 성공, 원본과 동일한 7쪽 |
| 승인된 정산보고서 HWPX | output의 v2, review_log의 W2 5점 승인 | 구조/렌더 통과. 별도 재패키징 사본도 구조/렌더 통과 |

현재 파일 해시는 이번에 기록했다. 과거 검토 로그는 기존 문서의 승인 이력이며 새 문서나 구조 변경 승인으로 전용하지 않았다. 실무 원본은 통합시험에 직접 투입하지 않고 사본만 사용했다. 배포 패키지에 학교 자료를 넣거나 외부에 전송하지 않았다.

## 실제로 실행한 것

- 구조·렌더 명령 **28회: 27회 통과, 1회 렌더 FAIL**. 한글 COM은 직렬 실행했다.
- 기안문 8건의 제목 스타일은 모두 같은 `charPrIDRef=10`, 12pt, bold이며 header와 페이지 여백도 베이스와 동일했다. 기존 일반 가통·회신형·기안문과 비교용 PNG를 직접 열어 배치를 확인했다. 이 판독의 수행자는 Codex이며 사람 교사의 새 판독으로 기록하지 않았다.
- **Codex와 Claude 실제 도구**에서 기존 8건의 스타일·여백을 대조했다. Claude는 6개 활동을 모두 보존한 초안 표를 작성하고, 데이터 5행에서 6행으로 늘릴 구조 변경 승인이 필요하다고 보고했다.
- 두 앱에서 긴 문구 161자(공백 제외)를 `cell:1:2:2`에 넣는 편집을 각각 한 번 실행했다. 실행기가 계산한 예산 24자를 초과해 **입력 단계에서 exit 1로 거절, HWPX 출력 없음**을 확인했다. 예산 우회 플래그·새 승인·가짜 판독을 만들지 않았다. 저장 slots.json의 11자와 현재 추정 예산 24자는 서로 다른 값이지만 161자는 둘 다 넘는다.
- Codex 최초 묶음 실행은 검사 결과를 JSON에 저장한 뒤 보고서 작성 전에 시험 실행기의 300초 제한에 걸렸다. 원시 출력을 보존하고 같은 세션에서 이미 얻은 결과의 보고만 이어갔다. 성공한 재실행으로 시간 초과 기록을 덮어쓰지 않는다.

## 변환 렌더 FAIL의 확인 결과

새 COM 변환 사본의 렌더 검사는 논리 텍스트에 없는 `◯`를 발견해 실패했다. 원본 HWP에서도 같은 위치에 이 원문자가 있었다. 원본·변환본을 각각 PDF로 내보내 **7쪽 전체를 72dpi 픽셀 비교한 결과 모든 쪽이 동일**했다. 원본에서 이어진 표시를 검사기가 잔재로 의심한 것으로 보이며, 관측된 변환 손상은 없다. 기존 FAIL 결과는 그대로 유지하고 원본 대조 근거를 추가했다. 이 한 사례 때문에 공통 잔재 검사를 끄지 않았다.

## 34개 행의 자료 부족 사유 정정

| 관련 사례 | 행 수 | 현재 확보한 자료 |
|---|---:|---|
| 09 새 양식 등록 | 2 | 일반 가통 실물·슬롯·출처·기존 검토/등록 이력 |
| 11 복수 용도·기안문 계보 | 4 | 실제 승인 기안문 8건, 공통 베이스, XML/COM 대조 |
| 14 학교 정책 유지 | 8 | 일반 가통 실물과 기존 정책/양식 기록 |
| 23·24 일반/회신 가통 전체 흐름 | 4 | 두 양식의 실물·슬롯·PDF·배치 확인 |
| 25 행 부족 | 4 | 데이터 5행 회신형과 6개 활동 원문. 승인 없는 경우의 실제 앱 보류 관측 |
| 26 셀 예산 초과 | 6 | 실제 셀 주소·예산과 긴 문구, 두 앱의 실제 입력 거절 |
| 32 HWP 변환·재패키징·폴백 | 6 | 실제 HWP, COM 변환본, 승인 변환 결과, 재패키징 비교 사본 |
| 합계 | **34** | 자료 없음 사유 해소. 개별 인수 완료 여부는 별도 |

**34건을 모두 평가 pass로 바꾼 것은 아니다.** 기존 실제 학교 자료를 쓰는 이번 로컬 시험과 최초 평가의 가상학교·독립 앱 조건을 구분한다. 시험자료는 준비됐으므로 이어지는 개별 앱 시험을 실행하면 된다. 원래 평가 기록을 그대로 보존하고 행별 자료 상태 정정을 별도 파일로 남겼다.

내가 계속 처리할 수 있는 범위는 사본 준비·출처 연결·슬롯/여백 대조·변환·렌더·자동 검사·실제 앱의 오류 처리·시험 초안 작성이다. 실제 사람이 응답해야 하는 등록/문안/구조/최종 검토가 필요한 분기는 검토할 구체적인 결과까지 준비한 뒤 진행한다. 외부 PC 시험은 제외하며 배포 권리 확인은 별도 조건으로 남는다.
