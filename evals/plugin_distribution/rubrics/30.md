# 30. 동료 교사 PC의 첫 사용 — 평가자용

- 계획 단계: 7
- variant별·대상별 독립 기록. 총 1개 행.
- 정답 근거: 개선 계획 7단계와 AGREEMENT.md. 현재 미완성 코드는 정답이 아니다.
- fixture 준비: FIXTURES.md의 fresh_environment, native_teacher_form, release_pair.
- 실행: cases/30.md의 입력을 고정한 뒤 해당 variant 절차를 수행한다. CLI 연결은 CONTRACT.md를 사용하되 실제 --help와 후보 버전을 먼저 기록한다.
- 앱 사례는 실제 선택 앱에서 새 문맥으로 실행한다. CLI/모의 이벤트는 대체 증거가 아니다.

## 필수 관측

- **C1** 실제 다른 PC 또는 새 사용자 환경 증거와 실제 교사 조작/응답이 있다. 개발자 CLI 대리 실행을 교사 첫 사용으로 세지 않는다.
  - 증거 종류: environment, transcript, human_review. 치명 항목: 실패는 다른 성공으로 상쇄 불가.
- **C2** 설치→등록→작성→검증→검토→업데이트가 완료되고 작업 자료를 보존하며 다음 행동을 교사가 이해했는지 확인한다.
  - 증거 종류: pipeline, delivery, integrity. 치명 항목: 실패는 다른 성공으로 상쇄 불가.

## 판정

공통 G1/G2도 함께 적용한다. 안전한 거절·미확인 보고가 기대 결과면 행동 검사는 pass일 수 있으나 문서 완료 실적은 별개다. 미실행·미구현은 pending, 실제 필요한 환경/fixture/사람 응답 부재는 blocked, 관측된 명세 위반이나 거짓 성공 주장은 fail이다. exit 0 또는 JSON의 pass 단독으로 평가 pass를 기록하지 않는다.

변조 variant는 정상 대조군에서 시험 사본의 지정 요소 하나만 바꾼다. 변경 대상·전후 해시·대조군 결과를 기록하고 원본이나 평가 기준을 수정하지 않는다. 실제 사용자 입력이 필요한 후속 단계는 OPERATOR.md에 따라 대기한다.
