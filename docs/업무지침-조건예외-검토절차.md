# 업무 지침의 조건·예외를 실제 문서에 적용하는 절차

W1·W2에서 지침을 근거로 의무, 기한, 금액 또는 누락·보완사항을 제시할 때 적용한다. 기존 도구 조회 후 초안 작성 전과 최종 검토 때 수행한다. 근거 조회의 연결 방식은 [업무지침-MCP-연결.md](업무지침-MCP-연결.md)를 따른다.

## 적용 판단 기록

관련 항목마다 아래 정보를 작업 검토 기록에 남긴다. 일반적인 안내 항목 모두에 불필요한 조건을 만들어 넣지는 않는다.

| 항목 | 기록할 내용 |
|---|---|
| 원칙 | 원문이 정한 대상·행위·기한·단가와 의무 수준 |
| 예외·재량 | 같은 조항의 단서, 표의 주석, 계속 쪽, 인용 조항, 별도 교부 조건. 확인한 범위에서 없으면 그 범위를 명시 |
| 사례 사실 | 사용자가 확인했거나 문서·기관 자료에서 확인한 적용 조건과 출처. 장소명만으로 기관 소속을 추정하지 않음 |
| 미확인 사실 | 판단을 바꿀 수 있지만 아직 확인되지 않은 조건. 일반적인 ‘추가 확인 필요’로 뭉뚱그리지 않음 |
| 판단 | 이 사례에 적용 / 해당 없음 / 재량·생략 가능 / 사실 확인 필요 / 원문 관계 미확정 |
| 근거 | 원문 판본·PDF 파일 순번 또는 문단·셀 주소와 근거 ID. 일반 원칙뿐 아니라 적용한 예외도 연결 |

미확인 사실 때문에 적용 여부를 모르면 ‘답사 절차가 빠짐’처럼 실행 항목을 추가하지 않는다. ‘이용 기관의 직속기관 해당 여부가 미확인되어 답사 생략 적용을 판단할 수 없음’처럼 필요한 사실을 특정한다. 먼저 기존 문서와 이용 가능한 자료를 확인하고, 거기서 해결되지 않을 때 사용자에게 그 사실을 묻는다. 기관 자료를 조사해도 개별 학교 지침을 school_task_guide에 등록하는 범위로 확대하지 않는다.

서버가 지원하지 않는 사례 조건은 Hwp_doc 검토 기록에서 확인한다. 요청 스키마에 없는 task_facts를 임의로 만들어 보내지 않는다. 서버가 missing_fields를 반환하지 않았더라도 원문에 조건이 있으면 적용 판단을 생략하지 않는다.

## 최종 문안과 대조

1. ‘필수·해야 한다·보완 필요’라는 문장마다 적용 대상과 예외 검토가 기록되어 있는지 확인한다.
2. 원문에 있던 생략 가능·재량·권장을 요약하면서 지우거나, 필수 또는 자동 면제로 강화하지 않았는지 대조한다.
3. 조건이 불명확한 항목을 확정 의무나 실제 미이행으로 바꾸지 않았는지 확인한다. 단순히 partial 표시를 붙인 것만으로는 충분하지 않다.
4. 사업별 교부 조건, 대상자 구분, 과목·학기, 기관 유형 등으로 결론이 달라질 때 그 조건과 근거가 최종 설명에도 남아 있는지 확인한다.
5. 판단을 바꿀 사실 하나를 반대로 가정했을 때 결론이 어떻게 달라지는지 점검한다. 결론이 달라져야 하는데 같다면 조건을 빠뜨렸는지 재검토한다. 이 가정은 검증용이며 실제 사건의 사실로 기록하지 않는다.

확인되지 않은 적용 판단은 그 항목을 보류하고 확인된 나머지 문서 작업을 계속한다. 지침 판단 대조 결과와 HWPX 구조·렌더링 검증 결과를 구분해 보고한다.

## 이번 보완의 한계

이 절차는 Hwp_doc 작성 에이전트에 적용하는 검토 절차다. 문장 의미를 기계적으로 보증하는 새 검증기나 MCP 조건 분기 구현은 아니다. 체크리스트를 채웠다는 사실만으로 올바른 해석이 증명되지는 않는다.

school_task_guide에서는 원문 대조 후 필요한 조건과 예외를 규칙에서 분리하고, 실제 작성 클라이언트의 최종 문구까지 확인하는 인수 사례를 추가해야 한다. 이번 조사에서 그 서버의 코드·데이터·색인은 변경하지 않았다.
