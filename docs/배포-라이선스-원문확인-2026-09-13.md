# 배포 라이선스 원문 확인

2026. 9. 13. · Hwp_doc · 사용자 요청에 따라 실제 저장소·공식 안내·고정 버전 설치 배포판의 라이선스 파일을 확인했다.

**현재 배포 후보를 재배포 가능으로 확정할 수는 없다. 핵심 원인은 Canine89/hwpxskill의 재배포 허가 미확인이다.** 의존성에 대해서는 단순 메타데이터보다 구체적인 조건을 확인했다. 원문을 확인했다는 사실과 배포 형태가 그 조건을 충족한다는 판단은 구분한다.

## 핵심 업스트림

[Canine89/hwpxskill](https://github.com/Canine89/hwpxskill)의 현재 main 트리 `cb5f25b6557b47b0339398d3b5d45a57bdcb4b28`를 GitHub API로 조회했다. 재귀 트리는 잘리지 않았고 LICENSE/LICENCE/COPYING/NOTICE 이름의 파일은 0개, 저장소 license 필드는 null이었다. README·SKILL에도 재배포 라이선스 선언을 찾지 못했다.

더 직접적인 근거는 2026. 8. 25. 등록된 [이슈 #4: 루트 LICENSE 파일 추가 요청](https://github.com/Canine89/hwpxskill/issues/4)이다. MIT/Apache-2.0 등의 라이선스 추가를 요청한 이슈가 열려 있으며, 조회 시 댓글은 0개였다. 이 요청 자체는 작성자의 허가가 아니다.

GitHub 공개 저장소의 열람·포크 권한과 코드를 별도 플러그인에 포함해 재배포할 권한은 같지 않다. [GitHub 공식 설명](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository)도 라이선스 부재 시 일반 저작권 규칙이 적용된다고 설명한다. 공개 저장소이거나 README에 설치 명령이 있다는 이유로 MIT/Apache로 간주하지 않는다.

따라서 현재 사용 중인 업스트림 코드와 그 수정본, 포함 템플릿에 적용되는 실제 라이선스 또는 권한 있는 저작자의 재배포 허가가 필요하다. Hwp_doc 자체 추가 코드에 라이선스를 붙여도 이 항목이 자동 해결되지는 않는다. 이번 확인 중 작성자에게 메시지나 이슈를 보내지는 않았다.

주요 라이선스에는 조건부 재배포 허용 경로가 있지만, 위 표는 전체 결합물의 라이선스 호환성이나 모든 전이 의존성의 조건 충족을 확정한 법률 판단이 아니다. 특히 PyMuPDF 적용 경로와 혼합 구성요소의 포함 범위를 정하지 않은 상태에서 “모두 배포 허용”으로 바꾸지 않는다.

## 현재 패키지에 대한 적용

현 배포 허용 목록은 Hwp_doc/스킬 코드·템플릿·설치 스크립트를 대상으로 하며 Python wheel이나 전체 venv를 포함하지 않는다. 의존성 설치는 별도 pip 경로다. 이 범위와 향후 오프라인 설치 묶음은 다르게 검토해야 한다. Python 패키지 라이선스가 확인되어도 한글 프로그램/보안모듈/템플릿·이미지 자산을 마음대로 재배포할 권한을 의미하지 않는다.

현재 남은 결정은 다음과 같다.

1. Canine89/hwpxskill 코드·수정본·포함 자산의 명시적인 재배포 허용 근거 확보.
2. Hwp_doc 자체 추가 코드의 배포 라이선스 선택.
3. PyMuPDF의 AGPL/상용 적용 경로와 결합·배포 형태 확인. 다른 렌더러로 바꾸는 선택은 구현·품질 검증이 필요한 별도 결정이며 이번 요청으로 교체하지 않았다.
4. 실제 포함 파일별 고지·권리·개인정보 검토와 의존성 조건 이행 확인.

rights.pending.json의 승인 필드는 바꾸지 않았다. 이는 원문을 안 읽었다는 뜻이 아니라, 확인한 조건을 충족한 배포 승인으로 잘못 승격하지 않았다는 뜻이다. 앞선 보고서의 pywin32=PSF, et-xmlfile=MIT, xlrd=BSD라는 요약은 이 문서의 구성요소별 설명으로 보완한다.
