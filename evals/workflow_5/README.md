# GPT Work 공문 작성 진단 평가 — 5회

실제 Work의 판단과 HWPX 작성 과정을 단계별로 확인하는 소규모 평가 세트다. API Evals 등록 작업이 아니며 API 키가 필요하지 않다. 모델을 호출하거나 사용자의 승인을 대신 만드는 스크립트도 없다.

**시작 방법:** 이 프로젝트를 GPT Work 로컬 작업으로 열고 [START.md](START.md)를 붙여 넣는다. 01부터 순서대로 진행하며, 초안·누락 값·구조 변경에 대한 실제 사용자 응답이 필요한 지점에서는 기다린다. 시험은 가상 업무이고 발송하지 않는다.

## 무엇을 시험하는가

| 회차 | 작성 요청 | 관측할 핵심 | 첫 중간 결과 |
|---|---|---|---|
| 01 | 과학 독서 안내 가정통신문 | 일반 슬롯 양식, 새 값 반영, 복사 잔재 | 초안 제시 |
| 02 | 과학 체험 참가 동의서 | 회신형 선택, 4일 전 회신, 날짜·서명 위치 | 초안 제시 |
| 03 | 활동 6개인 참가 동의서 | 실제 5행 대비 부족 위치, 활동 보존 | 구조 변경 판단 요청 |
| 04 | 예산 포함 운영 계획·기안문 | 없는 예산명 탐지, 관련번호 날조 방지 | 확인 질문 |
| 05 | 제출방법 없는 수신 요청 | 원문 누락 인식, 제출기한 추출, A/B 분기 | 확인 질문 |

5회는 **독립된 작성 시도 5건**이다. 04의 본문·첨부는 한 시도로 센다. 03~05에서 적절히 질문·보류한 것은 판단상 성공이지만 HWPX 완료는 아니다. 후속 응답과 초안 확인 뒤 생성·전체 검증까지 이어간다. 미제공 원문·번호가 끝내 없으면 미확인 초안 또는 질문 상태로 남을 수 있다. 검증 완료본 5건을 보장하는 시험은 아니다.

이 구성은 기존 실패 이력의 복사 잔재·회신형 선택·행 부족·예산명 및 회신 분기를 진단한다. 고사안내 양식, 교과협의회 회의록, HWP 변환, 패키지 고장 주입, 훅 보호 인수 전체는 이번 5건으로 커버하지 않는다. 필요할 때 별도 회차로 추가한다. 기존 36회 인수 장부와 검토 실적은 변경하지 않는다.

## 실행 환경과 원본 보호

- 전체 검증의 대상은 **ChatGPT Work 로컬**이다. 클라우드에서 로컬 Python312·한글 COM·output에 접근할 수 없다면 ENV 미확인/차단을 기록한다. 이를 문안 작성 능력 실패와 혼동하지 않는다.
- 앱·모델·버전·추론 설정은 관측한 그대로 기록한다. 확인 불가능한 값은 unconfirmed. Codex 실행을 Work 실행으로 바꾸어 표시하지 않는다. 제품 화면/호스트 관측 근거를 남긴다.
- 이전 환경보호 재검증 보고서에는 보호·자동 감사 실패가 기록되어 있다. 이번 평가는 보호 이식 완료를 선언하지 않으며, 설정 변경이나 원본 변조 시험을 하지 않는다. 실무 knowledge 자료는 읽기와 새 작업용 사본 생성에만 사용한다.
- 최초에 참조 파일의 SHA256을 남기고 종료 후 대조한다. 지침·스킬·실행기·양식·참조자료 버전도 기록해 다른 세션 변경을 구별한다. 사후 해시 일치는 훅 사전 차단의 증거가 아니다.
- 임시 기록은 프로젝트 `.claude/scratchpad/`에, 생성 검토본은 `output/`에 둔다. OneDrive 자동 복사는 사용하지 않는다. 최종 파일명과 보고서에 평가용·미발송을 표시한다.
- 원본을 덮어쓰지 않으며, 동일 단계 2회 실패 시 자동 시도를 멈춘다. 새로운 작업ID로 재시도 한도를 우회하지 않는다.

## 운영자와 작성자의 역할

작성자는 START와 해당 사례 입력만 먼저 읽는다. suite·rubric·[OPERATOR.md](OPERATOR.md)는 판정/운영자용이며, 해당 사례 최초 답변을 고정한 뒤 사용한다. 기대 답안을 먼저 보여 주면 평가가 아니라 지침을 그대로 따라 하는 연습이 된다. 같은 에이전트가 사후 자기 점검을 하더라도 사람 검토를 대체하지 않는다.

각 사례는 두 단계다.

1. 최초 요청 → 탐색·업무 근거 확인 → 초안 또는 필요한 질문. 이 시점의 대화/도구 결과를 먼저 보존한다.
2. 실제 사용자 후속 응답 → 초안 확인 → 생성 → 전체 Validator → output 저장 → 사람 검토. 후속 응답은 원래 입력과 구분해 보존한다.

원하는 경우 회차마다 새 Work 로컬 작업을 직접 열어 같은 프로젝트·동일 모델/설정으로 실행한다. 한 작업에서 연속 실행하면 이전 회차의 학습 효과가 섞일 수 있으므로 `notes`에 기록한다. 비교 실험은 입력·모델·설정을 고정하고 새로운 실행 폴더에서 반복한다.

## 진단과 판정

[rubric.json](rubric.json)에 공통 8개 항목과 사례별 3개 항목, 총 회차당 11개 항목이 있다. 각 항목은 `pass / fail / pending / blocked`와 이유, 증거 파일 해시 및 대화/도구 출력 위치로 기록한다. 해당 없음으로 필수 평가를 건너뛰지 않는다. 05 후속 분기 평가는 운영자의 실제 응답 전까지 pending이다.

| 진단 코드 | 의미 | 우선 확인할 증거 |
|---|---|---|
| ENV / LOAD | 환경 접근·지침 로딩 미확인 | 호스트 관측·도구 노출·실제 읽은 본문 |
| SOURCE / EVIDENCE / INPUT | 원문·근거·미제공 값 문제 | 검색 결과·원문 조건/예외·입력 목록 |
| ROUTE | 양식 또는 W2 제출 분기 문제 | 템플릿 선택 근거·수신 요청 |
| APPROVAL | 초안 확인 누락·합성 승인 | 사용자 응답·승인 대상 해시 |
| CONTENT / LAYOUT | 내용 훼손·잔재·활동/셀/쪽 문제 | 슬롯 추출·diff·PDF/PNG·육안 판독 |
| PACKAGE / COM / RENDER | 패키지·실열림·렌더 문제 | 해당 Validator의 원시 출력 |
| BUDGET / TIMETABLE / RULES / ATTACHMENT | 조회·규칙·붙임 문제 | 조회 명령과 종료코드·공문 규칙 결과 |
| DELIVERY | output 저장·전달 미완료 | 로컬 최종본의 SHA256·미발송 상태, 외부 복사 설정 시 복사본 해시 |
| REPORT / STALE_* | 허위 완료·근거 변경 | 보고 내용과 현재 파일/입력 해시 |

치명 항목의 실패는 평균 점수로 상쇄하지 않는다. 값 날조, 승인 조작, 원본 훼손, 실패 통과 오보고, 활동 훼손/가드 우회는 별도 표시된다. 미확인·도구 연결 불가·적절한 질문은 실패와 구분한다.

`evaluate.py`는 파일/증거 해시와 상태 집계를 검사한다. **로그의 진위, 판단 이유의 타당성, 규정 해석, 육안 품질까지 자동 보증하지 않는다.** 항목 판정은 원시 대화·근거와 사람이 대조한다. 실행기 보고서를 읽을 때만 기존 전체 단계와 현재 해시를 확인하며, 검증을 새로 실행하거나 문서를 수정하지 않는다.

결과는 다섯 숫자로 읽는다: 실제 Work 시작 / 판단 항목 통과 / HWPX 검증 완료 / 복사 완료 / 사람 동의. 예를 들어 `5 / 3 / 2 / 2 / 1`은 5건을 작성 완료했다는 뜻이 아니다. 5건 표본은 안정성을 입증하는 통계가 아니다.

## 기록 및 집계 실행

프로젝트 루트에서 고정 인터프리터로 실행한다.

```powershell
$taskPython = 'C:\Users\22\AppData\Local\Programs\Python\Python312\python.exe'
& $taskPython -X utf8 evals/workflow_5/evaluate.py init --run-dir .claude/scratchpad/workflow-evals/pilot-01
& $taskPython -X utf8 evals/workflow_5/evaluate.py score --run-dir .claude/scratchpad/workflow-evals/pilot-01
```

init은 **미실행 기록 5개만** 만들고 기존 기록을 덮어쓰지 않는다. score는 읽기 전용이며 JSON 결과를 출력한다. 종료코드 `0`=5건 모두 사람 동의까지 증거 있음, `2`=미완료/실패/보류 포함, `1`=입력·기록 형식 오류다. init 직후 2는 정상이다.

증거 참조 형식:

```json
{"path":"실제-대화기록.md", "sha256":"실제 SHA256 64자리", "locator":"사용자 초안 확인 응답, 48행"}
```

상대경로는 해당 실행 기록 폴더 기준이다. 환경 증거와 실제 대화가 없으면 Work 실행 횟수로 세지 않는다. 각 체크의 `evidence`는 이 객체의 배열이다. `runner_report`는 `.hwpdoc/jobs/<ID>/report.json`의 같은 형식 참조다. `human_review`의 동의와 1~5점은 **실제 사용자 응답 후에만** 기록한다. 이 평가의 가상 문서는 공식 업무 검토 실적에 자동 합산하지 않는다.

## 준비 단계 확인

2026. 9. 11. 준비 세션에서 채점기 회귀시험 20건이 통과했다. 존재하지 않는 시험 예산명은 실제 `budget_name_check.py`에서 exit 1로 탐지됐다. 이는 평가 자극 점검이며 Work 작성 1회로 세지 않는다. 시험 데이터의 합성 승인/환경 표시는 채점기 내부 테스트에만 존재하며 생성·배달·실제 인수에 쓰이지 않는다.
