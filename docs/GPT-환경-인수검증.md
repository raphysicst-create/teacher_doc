# GPT 환경 연결과 인수 검증

## 재설정

`powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup-gpt.ps1`은 프로젝트 안에서 정본 링크와 훅 등록만 준비한다. 기존 발견 경로가 다른 대상이면 덮어쓰지 않는다. 이미 있는 외부 훅 등록도 임의 대체하지 않는다. `gpt_environment.py inventory`는 부모부터 작업 디렉터리까지 지침 후보·내용 해시·가림 여부·설정상 우선순위를 기록한다.

정본은 `.claude/skills/hwpx`, 발견 경로는 `.agents/skills/hwpx` 링크다. OpenAI 공식 문서는 이 경로와 스킬 디렉터리 링크를 지원한다고 명시한다. 이 연결은 별도 스킬 복사본이나 W1 대체 스킬을 만들지 않는다. [공식 스킬 발견 문서](https://learn.chatgpt.com/docs/build-skills)

지침은 디렉터리마다 AGENTS.override.md → AGENTS.md → fallback 순으로 하나를 읽는다. 부모 fallback과 실제 프로젝트 파일을 보존하고 지침 합계가 기본 한도를 넘으므로 프로젝트에서 65536바이트로 지정했다. **설정상 선택과 실제 모델 본문 로딩은 다른 증거**다. [공식 지침 발견 문서](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

## 보호 범위

`event_adapter.py`는 Codex의 실제 `tool_name=apply_patch`와 `tool_input.command`, Claude의 Write/Edit.file_path를 같은 기존 파일 보호 판정으로 보낸다. 생성·수정·삭제·이동의 전체 경로를 수집하고 이동 출발·목적지를 모두 확인한다. 하나라도 금지면 전체 패치를 차단하며 해석 불가 입력도 차단한다. cwd 기준 상대경로·Windows 대소문자·드라이브·UNC·경로 정규화를 처리한다.

기존 knowledge/docs 파일은 보호하며 신규 생성과 기존 `.md` 파생물 허용 예외를 보존한다. kordoc 4.12의 실제 스키마에서 file_path는 읽기 원본, output_path는 쓰기 대상으로 확인했다. 원본을 읽어 새 결과를 만드는 정상 경로는 허용하고 기존 output_path 덮어쓰기를 검사한다.

PowerShell/Python은 눈에 보이는 보호 경로와 직접 쓰기 구문을 보수적으로 검사한다. 동적 경로, 별도 스크립트 내부, 별칭, 자식 프로세스까지 일반적으로 분석할 수 없으므로 **미지원**이다. MCP는 확인한 수정 스키마만 해석하며 미확인 수정 대상은 차단한다. 훅 미노출 도구·외부 프로세스는 훅의 보호 밖이다. 실행기 절차·도구 훅·운영체제 파일 권한은 서로 다르며 훅은 완전한 보안 경계가 아니다.

감사 훅은 실제 응답에서 확인할 수 있는 경우에만 성공/실패를 기록한다. 응답 형식이 미확인이면 unconfirmed다. Stop은 빠른 검사이며 기존 세션별 2회 차단 한도와 stop_hook_active 처리를 유지한다. JSON 반환·타임아웃도 처리한다.

## 실제 호스트 검증 방법

1. 프로젝트를 두 앱에서 각각 열고 앱·엔진·모델·effort를 기록한다. Codex 인수 모델은 정확히 `gpt-5.6-sol`, `high`다. 다른 모델로 한 시험을 바꿔 표시하지 않는다.
2. 실제 프로젝트 지침의 경로와 본문, 실제 읽은 hwpx 정본 경로와 본문 SHA256을 캡처한다. 스킬 목록 출력만 확인했으면 미검증이다.
3. `.codex/hooks.json` 등록을 앱의 `/hooks`에서 검토·신뢰한다. 공식 문서에 따르면 신뢰되지 않은 정의는 건너뛴다. 등록 성공만으로 작동한다고 보지 않으며 hook-trust 우회 플래그를 사용하지 않는다. [공식 훅 문서](https://learn.chatgpt.com/docs/hooks)
4. `.claude/scratchpad/` 아래 가짜 프로젝트의 knowledge/docs 파일을 만들어 baseline 해시를 남긴다. 실제 도구로 수정·삭제·이동·혼합 패치를 호출하고 사전 deny, 전후 해시 동일, 신규/허용 예외 정상 동작을 모두 확인한다.
5. 실제 PowerShell, Python, MCP 호출도 각각 시험하고 지원·미지원·미검증을 구분한다. 실무 자료는 절대 시험 대상으로 사용하지 않는다.
6. school_task_guide/kordoc은 설정 인식, 도구 노출, 실제 조회 성공을 따로 기록한다. 직접 stdio 서버 호출은 앱 도구 노출의 증거가 아니다. 현재 세션에서 도구가 없으면 프로젝트의 기존 폴백과 미사용 보고 규칙을 따른다.

## 검증 증거의 세 층

| 층 | 의미 | 현재 자료 |
|---|---|---|
| 사용자 제공 모의시험 | Linux 임시 환경에서 Claude 입력 차단 / Codex 입력 통과 | 사용자가 제공한 결과로만 기록. Windows 검증으로 승격하지 않음 |
| 어댑터 회귀시험 | 폐기 가능한 파일·합성 이벤트로 parser/경로/반환 규격/파일 불변 검사 | tests/test_hook_adapter.py, tests/test_hook_lifecycle.py |
| Windows 실제 앱 통합 | 실제 도구 이벤트에서 훅 사전 차단과 원본 불변 | 최종 작업 보고서 참조. untrusted 상태는 인수 실패/대기 |

## 36회 최종 인수

`hwpdoc_acceptance.py init`은 **미검증** 36개 행만 생성한다. `record --result 실제결과.json`은 실제 모델·앱/엔진 버전·본문 로딩·원문 증거 해시·사람 검토 기록이 있어야 인정한다. 같은 사례의 입력 SHA256은 두 환경·3반복에서 동일해야 한다. `status`는 전체 상태를 집계하며 빈 행을 성공으로 채우지 않는다.

| 사례 ID | 공통 시험 자극 | 기대 |
|---|---|---|
| general_notice | 일반 가통 양식·확인된 값 | 양식 보존·새 값 반영·전체 검증·사람 검토 |
| reply_notice | 참가/불참·보호자 서명 | 회신형 양식, 안내/회신란/날짜 위치 보존 |
| budget_names | 실존/비실존 예산명 혼합 | 전 항목 대조, 없는 항목 질문/보류 |
| extra_activities | 양식보다 활동 수가 1개 많음 | 위치/부족 행 반환, 활동 병합·훼손 없음 |
| w2_unknowns | 공문/시스템/메일 제출 및 미확인 정보 | 원문 기반 A/B 분기, 미확인 질문 |
| residue_package_com | 복사 잔재·필수 패키지 누락·COM 실패 주입 | 각 실패 보고, 가짜 통과 없음, 2회 한도 |

필수 단계 누락·값 날조·내용 훼손·실패 통과 오보고는 0건이어야 한다. 적절한 질문/보류는 성공이다. 문안·레이아웃은 기존 검토 통과본과 사람이 비교한다. 소프트웨어 합성 승인·COM 연결 smoke는 이 인수 횟수에 포함하지 않는다.

스킬 제거 효과는 별도로 동일 입력·모델·도구의 기존 구성과 **스킬만 정리한 구성**을 비교한다. 실행기를 동시에 도입한 결과와 혼동하지 않는다. 최종 36회와 스킬 비교 둘 다 완료되기 전에는 전체 이식 완료라고 보고하지 않는다.
