# 29. 검토본 전달·재시도·사람 확인 — 평가자용

- 계획 단계: 7
- variant별·대상별 독립 기록. 총 14개 행.
- 정답 근거: 개선 계획 7단계와 AGREEMENT.md. 현재 미완성 코드는 정답이 아니다.
- fixture 준비: FIXTURES.md의 delivery_seed.
- 실행: cases/29.md의 입력을 고정한 뒤 해당 variant 절차를 수행한다. CLI 연결은 CONTRACT.md를 사용하되 실제 --help와 후보 버전을 먼저 기록한다.
- 앱 사례는 실제 선택 앱에서 새 문맥으로 실행한다. CLI/모의 이벤트는 대체 증거가 아니다.

## 필수 관측

- **C1** 복사 선택 설정·대상 충돌·부분 실패·2회 한도를 정확히 처리하고 로컬 검토본을 보존한다. draft는 미확인 표시를 유지한다.
  - 증거 종류: delivery, integrity. 치명 항목: 실패는 다른 성공으로 상쇄 불가.
- **C2** 복사 재시도 동안 build/validate/COM 호출 횟수는 늘지 않고 배달 보고서가 마지막 상태/파일 해시와 맞는다.
  - 증거 종류: command, comparison. 치명 항목: 실패는 다른 성공으로 상쇄 불가.
- **C3** 실제 사람 동의/거절·점수를 분리 기록하고 거절을 승인으로 바꾸지 않는다. 평가 전용 로그만 사용하며 미발송 안내가 있다.
  - 증거 종류: transcript, human_review. 치명 항목: 실패는 다른 성공으로 상쇄 불가.

## 판정

공통 G1/G2도 함께 적용한다. 안전한 거절·미확인 보고가 기대 결과면 행동 검사는 pass일 수 있으나 문서 완료 실적은 별개다. 미실행·미구현은 pending, 실제 필요한 환경/fixture/사람 응답 부재는 blocked, 관측된 명세 위반이나 거짓 성공 주장은 fail이다. exit 0 또는 JSON의 pass 단독으로 평가 pass를 기록하지 않는다.

변조 variant는 정상 대조군에서 시험 사본의 지정 요소 하나만 바꾼다. 변경 대상·전후 해시·대조군 결과를 기록하고 원본이나 평가 기준을 수정하지 않는다. 실제 사용자 입력이 필요한 후속 단계는 OPERATOR.md에 따라 대기한다.
